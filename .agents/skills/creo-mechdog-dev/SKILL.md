# Creo MCP 开发

先识别任务：如果只是 WorkBuddy 黑盒验收或测试提示词，按 [AGENTS](../../../AGENTS.md) 的黑盒约定执行，跳过下面的开发者查证流程；不读取源码、SDK、配置、仓库状态或运行本地测试。

此 skill 面向 Git 检出的本项目。先读仓库 [AGENTS](../../../AGENTS.md)、[开发入口](../../../docs/DEVELOPMENT.md)，从唯一台账定位已有条目；新增工作先登记。规则以仓库当前文件和用户当次指令为准，不以历史验收代替当前状态。

默认维护者有软件工程经验但不熟悉机械/Creo。说明方案、进度和交付时，先按 [白话改动说明](../../../docs/development/CREO_CHANGE_EXPLANATION.md) 讲用户目标、前后行为、修改因果、独立验收依据和未证明范围，首次解释必要术语，再给源码/API/日志追溯；篇幅随任务缩放。区分软件契约、CAD 实测和机械工程判断，不用测试数量或 AI 自评替代可核对证据。

技术核验由开发 AI 承担：能从源码、SDK、参照数据和原生测量查证的内容自行核对，不让维护者代建参照特征、确认树节点/引用或判定几何是否正确。涉及手写/修改元素树时，按指南第 5 节的“开发 AI 自行完成参照取样与重建验证”执行闭环；实机须先满足当次授权，已授权范围内连续完成并汇报。权限不足或证据缺失如实标未验证，只询问必要授权、目标或无法自动确定的设计输入，不把技术验证转交用户。

按任务读取[中文 TOOLKIT 指南](../../../docs/development/CREO_TOOLKIT_GUIDE.md)：

- **查 API 或评估可行性**：读第 2–3 节。本机目标版本头文件 → 对应官方说明 → 官方示例 → 仓库实现。用 `rg` 和现有 `tools/sdk_decl.py` 定位；声明助手不提供所有权、错误码或元素树的完整依据。区分 C TOOLKIT 与 Object TOOLKIT C++。
- **对象、遍历、装配引用或字符串**：按需读 [API 使用模式](../../../docs/development/CREO_TOOLKIT_API_PATTERNS.md)，核对模型所有者/类型/ID、回调结束语义、组件路径、返回类型和缓冲区约定。按实际声明区分正式 API、示例辅助代码与项目助手，不按前缀或记忆套用。
- **新增或修复操作**：读第 4 节，核对输入/能力登记、桥接保护、原生分派和包含、结果投影及测试接线；只修改实际涉及的层。
- **曲面、元素树或跨 SDK 兼容**：读第 5 节，先找参照与独立验收目标，核对原始树/取值，再做单变量对照、引用重绑和重建验收；使用常量符号与实际依赖门控。没有完整文档时查证缺口，不猜值，不要求维护者确认技术正确性。
- **自动建模、改型或原生交付能力的验收**：按需读 [设计意图与验收](../../../docs/development/CREO_MODELING_ACCEPTANCE.md)，把目标映射到实际几何、坐标、装配依赖和保存后证据；区分执行与提交效果、预览与工程结论。沿用当前 C TOOLKIT 通道和实机确认，不直接运行外部案例的后端、会话或教材下载流程。
- **验证与交付**：读第 6 节。分别说明官方依据、当前实现、本次离线检查和历史/本次实测；头文件存在与编译成功均不代表运行或几何成功。

仅查资料时不启动服务、不编译或连接 Creo。需要原生构建或实机操作时，先按 AGENTS 核对用户当次明确确认的范围；不沿用历史授权，不清锁/unknown 保护，不擅自处理进程或模型。常量生成物、SDK 及官方整册资料留在本机，不复制进源码或附件。

自动匹配由宿主决定；显式使用可写 `$creo-mechdog-dev`。
