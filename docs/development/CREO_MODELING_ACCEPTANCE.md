# 自动建模能力的设计意图、验收与原生交付

本专题用于开发或评估涉及建模、改型、装配和模型交付的 MCP 能力。先按 [开发指南](CREO_TOOLKIT_GUIDE.md) 查 SDK 与接入点，再按本次需求选用下列检查；不要求每个操作执行全部项目。它不增加工具、运行后端或新的实机权限。当前接口和支持范围仍查包内能力登记、相关工作卡与 [COMPATIBILITY](../COMPATIBILITY.md)。

将验收解释给不熟悉机械/Creo 的维护者时，按 [白话改动说明](CREO_CHANGE_EXPLANATION.md) 提供“预期依据、预期、实际、证据”，区分软件、几何与工程结论；缺少实测时只列方法和待验证范围。

技术验收默认由开发 AI 准备依据、在获准范围内执行并判断，维护者接收可追溯结论，不承担手工操作或替 AI 确认几何的职责。涉及元素树参照时，使用开发指南第 5 节的自主取样/重建流程；缺少实际工程输入或授权时明确说明具体缺口。

## 1. 先把设计意图写成可测目标

从用户已有描述和既有工作卡确定目标，不重复询问已知信息；只对会改变实现或验收的缺口继续澄清。开发前把输入意图、实际几何和预期证据对应起来，避免仅按输入参数回显验收。

| 需求 | 需要明确的目标 | 可用的验收依据 |
| --- | --- | --- |
| 创建原生参数化特征 | 所需特征类型、引用、可编辑参数、生成实体或开放曲面 | 实际特征/状态及测量；文件扩展名、网格外观或一个正体积不足以证明目标特征已创建 |
| 改尺寸或改轮廓 | 主尺寸及受影响的孔、壁厚、配合件、组件位置 | 修改前后实测值、适用的尺寸/面积/体积或轮廓比较；分别记录输入期望和实际值 |
| 自动装配 | occurrence 身份、目标位姿、实际配合要求、涉及哪些源件 revision | 求解后的矩阵、约束状态和适用干涉/间隙检查；固定状态不直接证明功能配合成立 |
| 保存并交付 | 最终模型、装配引用文件、版本/数据根、允许的输出位置 | 本次最终文件的保存重载结果和依赖清单；不是同名旧文件或仅内存模型 |
| 工艺或使用要求 | 实际材料/工艺、关键功能、依据与适用表面/方向 | 明确的测量/计算/试验或可引用资料；缺少条件时保留未验证项 |

长度和角度输入按项目约定；实际模型单位、换算及原始查询码仍需按 [CODING_STANDARD](CODING_STANDARD.md) 核实。单位未知或测量未执行时不默认填成功值。容差应来自任务契约和适用精度，不能为迁就失败结果临时放宽。

解析公式或独立计算可用作理想期望的交叉检查，但不是 Creo 实测值；Python 校验、mock 或网格计算不能充当原生内核已经成功的证据。

## 2. 区分任务状态、操作效果与保存后结果

沿用本项目 MCP → bridge → 原生执行器的链路；按以下层次判断，不从前一层自动推导后一层。

| 层次 | 能说明什么 | 还需核对什么 |
| --- | --- | --- |
| 子进程启动或编译完成 | 运行准备的某一步完成 | 没有说明已连接、建模完成或输出可用 |
| 提交返回 `job_id` | 作业已接受 | 只轮询 `creo_get_job`；不重新提交；busy 拒绝按现有规则处理 |
| 某条操作执行成功 | 该操作执行的记录 | 对照 `execution_status` 与 `effect_status`；执行过的操作可能随后整体回滚，未知结果不能写成已提交 |
| 作业持久化终态 | 本次任务结果已登记 | 核对成功条件、实际几何断言和原始错误，不能只查日志是否含一个 PASS 字符串 |
| 保存重载验证 | 服务报告本次保存文件已重载并检查 | 修改功能还要核对对应参数、几何、组件与位姿证据；不能用历史作业或旧文件替代 |
| 预览或网格筛查 | 所显示/采样几何在该方法范围内的结果 | 不提升为特征可编辑性、连续曲面精度或工程功能已经通过 |

建模验收沿用 DEVELOPMENT 的 `status=succeeded`、`saved_file_reloaded_and_verified=true` 及适用的几何/回滚要求。效果状态定义查 [operation_results.py](../../src/creo_mechdog/operation_results.py)，回执投影查 [job_projection.py](../../src/creo_mechdog/job_projection.py)。字段未由接口提供时写“无法确认/未验证”，不拼造服务字段。

“重开最终文件检查”这一方法在本项目通过既有保存重载流程取得证据，不直接采用外部案例启动第二个 Creo 会话的步骤，也不自动擦除或重启用户会话。只读材料查证保持离线；任何原生构建、连接及测试先遵守 [AGENTS 当前确认规则](../../AGENTS.md)。返回旧任务终态也不保证通道空闲，其他客户端可能已经取得通道；不因遇到 busy 自动重交。

## 3. 草绘、坐标和改型依赖需要核对实际结果

- 草绘自动约束、局部原点及再生可能使目标轮廓与输入描述不同。对本次关键形状回读实际草绘/截面或原生几何，按需求验证轮廓、位置和方向；正体积不能代替尺寸正确。
- 如果修改建模策略会改变几何语义，例如直线、弧和样条之间的替换，先明确允许的几何目标和验收方法，不把临时绕行当成等价能力。
- 分清草绘局部、零件、组件、装配根与预览坐标。记录变换方向、矩阵约定与单位；本项目的行向量约定见 [ASSEMBLY_REBUILD](../ASSEMBLY_REBUILD.md)，求解后变换入口可对照 [component_transform.h](../../native/component_transform.h)。外部案例使用某轴为高度不构成本项目默认坐标定义。
- 源件改型后检查实际组件所使用的源 revision/快照。当前装配源快照语义与支持的更新路线以 ASSEMBLY_REBUILD 和当前实现为准；不要假定一次 regenerate/save 会把已有组件替换成源件新版本。
- 用户要求部件或整机参数化时，分别列出会联动的轮廓、配合件、位置、约束和验证目标；只改一个子零件不能报告整机联动已完成。修改验收目标须说明设计变化依据，保留原始失败数据。
- 装配保存后核对最终 occurrence、求解位置和实际约束。缓存检查快照有自己的时间与 revision，不能代替本次再生后的结果；嵌套、源件更新等支持边界查当前能力，不外推。

## 4. 原生文件集与证据交付

需要交付模型时，以任务实际产物为对象，不重命名覆盖用户基线、不手动清理旧作业目录。对装配确认引用依赖均在可交付范围；复制一个 `.asm` 文件或找到目录中最大的版本号，都不能证明交付文件集完整且属于本次验证。

按用户交付范围记录以下信息；这是报告内容指引，不表示现有 MCP 自动提供每个字段：

| 内容 | 记录要点 |
| --- | --- |
| 原生模型 | 实际文件及相对目录、零件/装配关系、依赖/外部参照范围；使用现有受管输出和装配交付入口，不另写隐藏复制流程 |
| 本次证据 | job_id/model_id、revision、操作效果、关键测量及单位、保存重载/回滚结果、原始错误、环境与源码身份 |
| 可追溯文件身份 | 在需要校验交付一致性时记录最终文件的大小或 SHA256；明确计算时点，不把哈希相同解释为几何或功能正确 |
| 预览 | 来自同一已核实产物的真实几何，标明坐标/变换、显示配色或网格近似；缺少实际几何则说明未生成预览，不用示意图充当本次结果 |
| 剩余事项 | 未提供的接口证据、未支持的输入/场景、未验环境及工程假设；与已验证结果分开 |

现有装配相关入口可读 [assembly_bundle.py](../../src/creo_mechdog/assembly_bundle.py)、[assembly_replay.py](../../src/creo_mechdog/assembly_replay.py) 和 ASSEMBLY_REBUILD；先核对具体接口能力，不能因模块存在就宣称任意依赖已能打包。现有 `native_bundle` 也可能返回 `complete=false`：核对返回的 `complete`/`missing` 以及清单中的未解析引用；目录存在或有 SHA256 不等于依赖完整，缺件应明确报告。后续开发若确需新增公开字段或导出流程，另按项目条目实现和验证。

## 5. 工艺结论保持其适用范围

只有任务涉及相应工艺要求时，才引入工艺资料与检查；通用 MCP 开发不强制安装某本教材或沿用某个产品的尺寸、材料和试验目标。

例如，注塑场景需要根据具体材料、表面、壁厚、抽拔方向及分型方案选择检查；金属或弹性体场景按实际工艺判断。缺材料或方向依据时说明缺口，不能把外部案例的一个角度或离散采样间距当成通用阈值。

对已有 CAD/网格测量，报告方法及覆盖范围：零刚体干涉不证明夹紧或密封，离散射线未检出问题不证明任意曲面可出模，几何健康不证明承载或量产条件通过。工程要求如需进一步分析、试验或人工工艺确认，在本次报告中明确未验证，不以“模型检查通过”概括所有结论。

引用教材或标准时记录实际查阅版本、章节/页码及适用条件；不能将摘要当成读过原件，也不主动下载或分发他人教材、模型及运行时。对缺少许可声明的外部项目，只将方法作为查证线索，不引入其文件或原文。
