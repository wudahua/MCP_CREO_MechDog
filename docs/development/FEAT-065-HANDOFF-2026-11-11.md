### A2. 本版改了什么（供写版本说明）

建议版本 **0.22.0**（MINOR：新增公开参数和输入形态，旧调用行为不变；公开工具数仍为 107）。

- `creo_surface_loft` 的 `sections`/`guides` 除草图外，再接受已有曲线 `{kind:'curve',id}` 和边 `{kind:'edge',id}`；首末截面可以是收敛点 `{kind:'point',id}` 或单点 `datum_points` 标签。
- `creo_surface_loft` 新增 `boundary_conditions`。目前只开放边来源的首/末截面上的 `tangent`；`curvature`、`normal` 和导线边界在提交前拒绝，并给出实测原因。
- `creo_measure_surface_group` 回执新增 `group.open_edge_records`，列出开放边的 ID、所属面与 quilt、长度和端点，最多 32 条，并附总数与截断标记。这是拿 quilt 边 ID 的公开渠道。
- 回执新增：`section_source_kinds`、`section_geometry_ids`、`section_sources`、`guide_*` 同名字段、`convergence_point`、`boundary_conditions`（含 `tan_cond_type`、`stretch`）、`tan_cond_tree`；`unverified_input_forms` 保留但恒为空。
- 实机证据（Creo 12.4.0.0）：
  - M3 驱动：实机 40 项全 PASS。
  - M4 相切驱动：实机 59 项全 PASS，两条接缝 G1 都是 0.0°，补面面积 982.5888 mm²。
  - 详见 [FEAT-065 工作卡](../work-items/FEAT-065.md)、[T2b 证据](../validation/feat065-t2b-tangency-2026-11-11/EVIDENCE.md)、[兼容矩阵中的开发分支一节](../COMPATIBILITY.md)。
- 未测：Creo 9/10、非平面相邻面上的相切、导线边界、`curvature`/`normal`、已有实体的模型（`surface_loft` 在这种模型里一律失败，是旧限制）、非 mm 单位、WorkBuddy 黑盒。

### B2. SDK 里找到的曲面能力入口（后续扩展可直接用）

| 头文件 | 内容 | 对本项目的意义 |
| --- | --- | --- |
| `Probbl.h` | 边界混合元素树：`BNBLN_1DIR/2DIR` → `DIR_CURVES` → 每条链一个 `STD_CHAIN_HOLDER` + `STD_CURVE_COLLECTION_APPL`；`BNBLN_TAN_COND` → `TNC_BNDRY`（`TAN_COND_TYPE`、`CONNECT_SURF_CHAIN`、`TAN_FLD_TYPE`、`STRETCH`、`ADV_VIA_CRV`）；`BBL_ADD_CLOSED` | `surface_loft` 的全部能力都在这棵树上。`TAN_COND_TYPE` 只文档化了 `TAN_COND_FREE`，相切的取值靠实测（B3） |

代码层的关键发现：
- `native/surface_loft.cpp` 原来就是用 `curve_collection` 把 `{kind:'curve',id}` 放进链容器的，外面只多了一道「必须是独立草图」的检查。所以放开曲线、边输入的改动量很小。
- `native/surface_group.cpp` 测量时本来就逐条收集了开放边的 ID、端点和长度，只是回执里只输出了数量。所以 T1b 是一次低成本的补全。

### B3. 没有文档的元素取值，怎么实测出来（这次相切的做法）

1. **先让内核补默认值**：只建 INCOMPLETE 骨架 → `ProFeatureElemtreeExtract` → 读回内核自动补出的树 → 修改 → `ProFeatureWithoptionsRedefine`。不要在创建树里写未文档化的元素：2026-11-01 的探针证明那样会让特征停在 UNREGENERATED。
2. **临时实验钩子**：在原生代码里读一个环境变量（这次叫 `MECHDOG_EXPERIMENT_TAN_COND`），把候选值写进抽取出的树。驱动启动 `server.py` 时带上这个变量，它会依次传给 runner 和 worker。**钩子不提交**：实验前备份源文件，结束后恢复，再写正式实现。
3. **选一个好判的几何**：两张平行竖直曲面带，用顶边作截面、不加导线。自由时补面是平面（800 mm²，z=10），所以只要有效果，面积和包围盒立刻会变。
4. **逐层确认**：
   - 第 1 轮：值 2、3 只换了曲面表示，形状没变（面积不变）→ 怀疑系数为 0。
   - 第 2 轮：加 `STRETCH=1` 后起拱 → 找到关键元素。
   - 第 3 轮：两端同号时成 S 形 → 发现方向问题。
   - 第 4 轮：单端试验，并用 `quilt_merge` + `creo_measure_surface_curvature` 测接缝 G1 → 得出下标与符号。
   - 第 5 轮：把一张曲面带反向画线（边方向和面法向都翻转），结果不变 → 规则与几何朝向无关。
5. **判读时的坑**：
   - G1 夹角只说明两侧法向平行，区分不了「顺着墙面延伸」和「折回贴在墙面上」（后者测出 180° 或 0°），所以必须同时看包围盒，确认补面在接缝外侧。
   - 非平面曲面的包围盒带约 0.12 mm 余量，不代表曲面外鼓。
   - `quilt_merge` 后面的 ID 会变，测 G1 时用成员序号 `faces=[0,1]` 最稳。
   - compact 回执里没有 `quilt_merge` 的 `result_quilt_id`，要用 `creo_get_job(detail="full")` 读。
6. **没找到依据就不发布**：值 3 改变了形状但接缝仍是 90°，值 4 与自由无法区分，所以 `curvature`、`normal` 照实拒绝，并写明实测原因。

### B4. 操作上的注意事项（这次踩过或差点踩的）

- **实机驱动运行期间不要改任何源码**：每个作业开始前都会按源码指纹判断要不要重新编译执行器，中途改代码会让后面的作业用上另一个版本。
- `bridge.py build` 很快结束，通常是复用了缓存。要确认缓存对应当前源码，可以比较 `build/source.sha256` 和执行器的时间戳。这次 17:16 的那次编译不是本会话发起的，但指纹与源码一致。
- 后台任务用工具自带的后台运行方式，不要在命令里加 `&`，否则拿不到完成通知。
- 同一时间可能有别的客户端在用开发服务。开测前先看根目录 `toolkit-channel.json` 和最近的 `jobs/`。
- 实机授权按次生效：本次授权只覆盖编译、建测试模型、M3 验收和 M4 试值。A4 第 1 步的旧驱动回归需要重新确认。
