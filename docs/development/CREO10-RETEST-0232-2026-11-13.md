# Creo 10 跨版本复测交接包（0.23.2 球鼻艏反馈批，2026-11-13）

按 [分批计划](../superpowers/plans/2026-11-13-feedback-0232-bulb-loft.md) 的 C2 准备。本文件只写操作、输入、判据与记录要求；执行者可以是报告方（42 机）或任何持有 Creo 10 + 匹配 SDK 的人。

本文件**不构成任何 Creo 10 可用结论**。12.4 的通过不能外推；每个场景的结论只能由执行者在自己的会话里记录。没有现场的项目写"未验证"，不制造条件。

## 0. 环境与前置

1. Creo 10 必须用**本机 SDK** 重编 worker（`bridge.py build`）。用 12.4 SDK 编译的 `build\creo_worker.exe` 在 Creo 10 上缺少常量与入口，连接会失败或缺能力，这不属于被测行为。
2. 只启用指向本项目的 MCP 服务；不改配置、不杀进程、不清锁、不动 `unknown` 保护。
3. 开始前 `creo_session_status` 记录 `server_version` 与 `release_numeric`（Creo 10 期望 `42`，以返回值为准，不按版本号推断）。
4. 每个场景用独立新模型，名字带随机后缀，避免会话内重名。

## 1. 场景 1：只读导出不被基线漂移挡住（BUG-121）

1. 新建 40×40×10 方块：`creo_execute_plan`，`model_name=ro10_<随机>`，operations 为 XY 面 sketch（矩形 `min[0,0]`/`max[40,40]`）+ extrude（depth 10，mode add）。
2. 同一模型提交 `[{"op":"export","format":"step"}]`，带 `model_id` 与 `expected_revision`。
3. 判据：作业 `succeeded`；**作业清单 `job.json`** 里 `readonly=true`、`readonly_source="inspection_only_plan"`。`creo_get_job` 的 `detail=compact` 不披露这两个字段，只读 compact 会误判，必须读清单。
4. 记录：两条 job_id、model_id、revision、导出文件路径、`creo_get_job` 原始终态。
5. 失败形态识别：若出现 `model_reconciliation_required: Saved feature/body count changed`，说明该版本上只读降级没有生效，按回归上报。

## 2. 场景 2：`surface_loft` 误拒回归（BUG-122）

1. 第一次：新模型 `loft10_<随机>`，三条 XZ 直线草图（offset 0/20/40，line (0,0)→(40,0)）+ `surface_loft`（`interpolation=smooth`）。期望成功，记录 `create_code`、`extract_code`、`feature_incomplete`、`kernel_completion`。
2. 第二次：同一模型再提交一组新草图 + `surface_loft`，带最新 `expected_revision`。
3. 两种合法结局，按实测记录，不预设：
   - 若本机已观测到内核签名（`kernel_completion=unsupported` + `create_code=0` + `extract_code=-18`，见 `build/toolkit_health.json` 的 `surface_loft_runtime`，按 worker SHA 键控）：`surface_loft` 应在**提交前**被拒——无 job_id、无新作业目录、模型里没有新特征，错误文本给出三条出路。
   - 否则：正常成功，`revision` +1，回执不含 `refused before a job`。
4. 这一场景是"先失败一次再成功"序列唯一可能出现的现场：第一次成功、第二次被拒即该序列；两次都成功说明本机未命中签名，不构成误拒证据。
5. 记录：两次 job_id（或被拒时的原始错误文本）、`surface_loft_runtime` 观测快照、模型特征列表（确认没有半成品特征）。

## 3. 场景 3：模板 XML 路线（BUG-123）

1. 第一次放样成功后，提交带 `template` 的 `surface_loft`：`file=templates/elemtree/loft_s3g3_creo12.4.xml`、`sha256=4ef01eed…`、`sections=3`、`guides=3`，输入形状与模板一致。
2. 判据：`tree_source="template_xml"`、`create_code=0`、`extract_code=0`、`feature_incomplete=false`、`load_code=0`、`element_errors.total=0`。
3. **解析失败是本场景的主要预期结果**（12.4 导出的 XML 在 10 上可能元素 ID/枚举不符）：`load_code != 0` 时把 `element_errors` 的 `line_number`/`column_number`/`message` 原样记下——这是"低版本缺哪个元素"目前唯一的机器答案，比终端输出可靠。
4. 负例各跑一次：删掉整段 `PRO_E_BNBLN_1DIR` 的形状 → 期望 `TEMPLATE_SHAPE_MISMATCH`；只写半行根元素的坏 XML → 期望 `TEMPLATE_TREE_LOAD_FAILED`。两者都不得留下特征（`feature_id=null`，模型特征数不变）。
5. 注意口径：模板只换**输入树**，创建后仍会执行 `ProFeatureElemtreeExtract`。因此即使 `create_code=0`，`extract_code=-18` / `feature_incomplete=true` 仍可能出现（BUG-120），不因模板而消失；这条必须如实记录，不得写成"模板路线在 10 上可用"。

## 4. 场景 4：STEP/IGES 导入（BUG-124，需要导入许可）

1. 准备一个合法 STEP 文件，记下绝对路径与 SHA256。
2. `creo_execute_plan`：只含一条 `import_geometry`（`format=step`、`profile` 绝对路径、显式 `sha256`），不带 `model_id`、不与其他操作混排。
3. 判据：作业成功时记录 `created_model_name`、`create_code`、`surface_count`、`area_mm2`、`quilt_closure`、`profile_path/sha256`，并做一次保存重载。
4. 许可缺失必须原样得到 `PRO_TK_NO_LICENSE`：这是环境结论，不是本卡失败，不要重试或换 profile 绕开；同样记录 `PRO_TK_UNSUPPORTED` / `PRO_TK_INVALID_FILE` 的原码。
5. 用同一流程再跑一次 IGES。
6. 额外观察（不阻塞）：纯曲面（非实体）样本、以英寸为单位的模型。英寸模型会被毫米校验回滚，属预期行为，需记录回执原文。

## 5. 场景 5：计划级断言（FEAT-067，可选）

1. bbox：新模型 40×40×10，断言 `{"bbox_mm": {"min": [0,0,0], "max": [40,40,10], "tolerance_mm": 0.001}}` → 期望 `succeeded`；同一模型再叠一块（offset 10、height 5）仍用原期望 → 期望 `failed`，消息含 `Bounding box assertion failed on Z`，`revision` 不变。
2. 面积：同款方块断言 `{"surface_area_mm2": 4800.0, "surface_area_tolerance_mm2": 0.5}` → 期望 `succeeded`；叠加后仍用 4800 → 期望 `failed`，消息含 `Surface area assertion failed: measured 5600…`。
3. 未知单位：若能在 10 上建英寸模型，期望两条断言都**失败**并说明长度单位不可换算为毫米；通过即为缺陷。

## 6. 报告要求

每场景单独成节，包含：工具调用与输入摘要、`job_id`/`model_id`、终态与原始错误文本、`revision`、保存重载结果、`creo_session_status` 的 `release_numeric` 与 `server_version`、以及 `build/toolkit_health.json` 里相关观测。

结论四态：**通过 / 失败 / 未验证 / 无法确认**。接口没有提供的构建身份写"无法确认"，不用推测补齐。

不接受：把本文件或 12.4 的结论抄成本机结论；没有并发调用却报告并发通过；为制造失败形态而杀进程或清保护。
