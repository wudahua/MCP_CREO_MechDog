## 0.43.0 反馈补修（2026-11-24）

- 报告方在官方源码包中采样 150 次，强制启动分支预期进入 `ready`，实际有 4 次进入 `timeout`。两段均使用假时钟后，因果探针连续 120 次通过。[0.43.0 反馈原件](../validation/feedback-0.43.0-2026-11-24/originals/bug175-forced-startup-deadline-flaky.md)
- 核验并解压 v0.43.0 官方源码 ZIP 后，用离线探针将强制启动分支首次模拟的 `-4` 探测延迟 1.1 秒。无延迟时通过，注入延迟后复现第二段 `timeout`。`_drive()` 收到 5 秒总预算，构建结束后按测试配置给连接阶段最多 1 秒。
- 两种启动场景需共用可控单调时钟和模拟等待，并隔离真实 Toolkit 锁与仓库运行目录。验收断言覆盖普通场景的陈旧会话诊断和强制场景的一次启动及就绪状态。
- 在 Windows x64 / Python 3.12 下运行针对性回归和统一开发检查，从解压的源码候选包连续执行至少 60 次，并重复 1.1 秒延迟对照。验收覆盖离线单测及 stdio 契约。
