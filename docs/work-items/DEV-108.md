# DEV-108 Windows CI 启动重试 ID 偶发重复

分类：**已交付 0.48.3**。P1。 [发布记录](../validation/RELEASE-0.48.3.md)

在托管 Windows CI 上，`tests/unit/test_startup_retry.py::StartupRetry::test_polling_keeps_the_retry_id_and_a_new_retry_gets_a_new_one` 连续两轮出现 `AssertionError: '<id>' == '<id>'` 失败（如 [主干运行 45994134069 第 2 轮](https://github.com/wudahua/MCP_CREO_MechDog/actions/runs/45994134069/attempts/2)）。

原因：Windows 默认 `GetTickCount64()` 与 `GetSystemTimeAsFileTime()` 时钟分辨率为 15.625 ms。当两次连续重试落入同一时钟刻度时，`CreoStartup._new_retry_id()` 基于 `os.getpid() + monotonic_ns + bridge.now()` 生成相同摘要，且 `_run()` 的 `updated_at >= self._requested_at` 判定误将前一次自己的 `state.json` 当作并发协调者已完成的结果而直接覆写 `self._state`。

范围与验收：
- `src/creo_mechdog/creo_startup.py`：为 `_new_retry_id()` 引入进程内单调计数器与高精度 `perf_counter_ns()`，并记录本次启动前已存在的共享快照 `retry_id`/`updated_at`，确保 `_shared_satisfies_attempt()` 不把本实例旧尝试的 `state.json` 误判为新协调结果。
- `tests/unit/test_startup_retry.py`：保留原两条核心断言，补充线程退出与新重试接受断言，并新增同刻度冻结时钟与跨进程协调区分的确定性回归测试；已在分支 `codex/dev-108-111-closeout`（提交 `207e9289`）的托管 Windows CI [运行 46002779873](https://github.com/wudahua/MCP_CREO_MechDog/actions/runs/46002779873) 首轮全量通过（4,569 项，10 跳过，0 失败，0 错误）。
