# BUG-121：只读读取被保存基线漂移挡住，写操作失败消息不给动作

## 当前摘要（2026-11-13）

分类：**部分交付，剩余待验收**。类型：缺陷/可用性。优先级：P2。目标版本：0.24.0（子项）；剩余未排期。

来源：`C:\Users\Administrator\Downloads\反馈包-球鼻艏-20261112` 主报告第 12.2 节，作业 `7d38c7c2b8d14f589fee876e875f9bd7`（`export format=step`，回执 `BUILD_FAILED: model_reconciliation_required: Saved feature/body count changed`）。

结论：反馈的"只读导出也被拦住"**在 0.23.2 源码上有前提**——`export` 工具本身以 `readonly=True` 提交，而原生准入的 `verify_saved` 早已被 `!readonly` 包住（`native/generic.cpp` 准入段）。真正会触发该回执的是**以可写方式提交**的 `export` 计划（`creo_execute_plan` 直接写 `{op:'export'}`）：Python 侧基线哈希可能仍然匹配，而原生准入用旧的 inspection 基线比对现场特征数，于是回滚。两者都真实存在，分别处理：

- 不修改模型的操作型计划在 Python 侧自动按只读准入（`readonly_source="inspection_only_plan"`），不再受基线漂移影响；
- 真正需要基线的写计划失败时，消息在原样保留原生文本后追加动作指引（`creo_reconcile_model` 的可用动作）。

## 现象与证据

- 反馈回执只有症状文本，没有说明"只读读取不受此比对约束"，也没说该用哪个 reconcile 动作。
- 反馈 12.2 建议 (a) 只读不受漂移影响、(b) 错误消息写明 action；两条都已落地。

## 本次改动

- `generic_bridge.py`：新增 `INSPECTION_ONLY_OPERATIONS`（`dump_tree`/`export`/`udf_inspect`/`mass_properties`/`surface_group_measure`/`surface_curvature`）；只读白名单复用该常量；当既有模型、计划非空且全部操作只读时自动降级为只读并记 `readonly_source`；`request.json` 与 `job.json` 均记录来源。
- `src/creo_mechdog/reconciliation.py`：新增 `admission_failure_message()`，对 `model_reconciliation_required:` 前缀追加一次性动作指引；已含 `creo_reconcile_model` 的文本不重复追加。
- `generic_bridge.py` 失败分支：保留 `result["native_message"]` 原文，`result["message"]` 与 job `message` 用追加后的文本。
