三项结论：

1. **离面轴确认无诊断**（任务 4 既定缺口成立）：轴明显不在草图平面内，失败文案只有内核通用句，既没有轴原点/方向，也没有"轴到截面平面距离 50 mm"这类可操作信息。用户无法区分"轴画错"与"截面不闭合"。
2. **圆边多段匹配 + 提示语无效**（新缺陷，非原计划项；归因已两次修正，现已定论）：初判"`center_mm` 未参与过滤"**不成立**——`native/geometry_selectors.cpp:129-133` 明确先按半径、再按 `selector_component_error(arc_center, center) <= tolerance` 过滤中心。

   **2026-11-20 实机复核（重启后重建同一模型，`creo_inspect_model(detail=full, section="edges")`）已证实**：两个凸台的整圈圆边各被原生拆成**两段半圆弧**，且两段参数完全一致——`id 99` 与 `id 100` 均为 `origin=[-40, 0, 20]`、`radius=20`、`span 0→3.142`；`id 101/102` 在 `[40, 0, 20]`；底缘同样成对（`115/116`、`117/118`）。因此 `center_mm+radius_mm+tolerance_mm=0.01` 必然同时命中两条，报"匹配 2 条边"是**正确判定**，不是过滤器失效。

   **唯一成立的缺陷是 remediation**：一个完整圆边被拆成两段后，用户按 inspection 报告的 `origin/radius` 选取永远得到"2 条匹配"，而提示仍建议"缩小 tolerance_mm"——这对同中心同半径的两段弧永远无效。正确指引应是"加 `point_mm` 选中目标弧段"或"改用 `{kind:'edge',id:N}`"，这正是 FEAT-068 A0 加 `point_mm` 分支要解决的场景。修复点在 `native/geometry_selectors.cpp::selector_edge_error` 的多匹配分支（需把"全部匹配同中心同半径"的事实传进去，`advanced.cpp:1737` 有同文案需同步），属原生文案改动，**未在本轮实施**。
