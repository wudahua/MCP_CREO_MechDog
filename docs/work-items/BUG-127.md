# BUG-127：worker 在 MCP 宿主进程树内恒返回 -4，缺少桌面启动复核路径

## 当前摘要（2026-11-13）

分类：**已完成**。类型：缺陷。优先级：P1。目标版本：0.24.1。

来源：报告 P-05 与第 11 节建议 1（0.23.1 安装验收）。关联 [BUG-005](BUG-005.md)：本条目只补可配置的复核路径，不改写 BUG-005 的根因结论。

## 问题或目标

报告环境（Creo 13.4.0.0 / Windows 11 24H2）已证实：

- Creo 侧健康：`trail.txt` 有 `user_initialize status 0` 与 `connected to Pro/E`，`support.inf` 显示 `mcp_applet_async.exe` 正在运行，无许可拒绝。
- 每次 worker 发起的连接在 84 ms 内返回 `toolkit_code=-4`（`PRO_TK_BAD_CONTEXT`）、`worker_exit_code=20`、`release_numeric=0`。
- 已排除 psf 位置、`-g:no_graphics`、许可三项变量；从 shell 直接跑 worker 同样为 `-4`。

推测根因是 MCP 宿主给子进程套了 Job Object：Creo 已经用 Explorer 的 `Shell.Application.ShellExecute` 逃出，但状态探针仍是 `subprocess` 直连。0.24.0 没有第二条启动路径，无法区分「进程上下文」与「Creo/许可」问题。

## 范围

包含：新增 `desktop_worker.py`，经 `Shell.Application`（explorer.exe 内执行）以隐藏窗口启动 worker，输出与退出码经临时文件回收、目录事后清理；启动前校验 Explorer 的会话、映像与用户 SID；`creo_worker_launch` 支持 `auto`/`direct`/`desktop`（缺省 `auto`），`auto` 仅在直连返回 `-4` 时复核一次，桌面失败回退直连并附 `desktop_retry`；返回值新增 `worker_launch`。

不包含：不改建模作业（`create`）的启动方式；不自动关闭 Creo；不修改宿主 Job Object；许可值不写入临时脚本（与桌面环境不同时直接放弃该路径）。

## 验收标准

| 环境 / 用例 | 命令或操作 | 可判断的预期结果 |
| --- | --- | --- |
| Windows / Python | `tests/unit/test_desktop_worker.py`、`tests/unit/test_toolkit_hints.py` | 脚本生成、许可拒绝、超时、桌面不可用、`-4` 回退与不采纳仍 `-4` 的桌面结果均符合预期 |
| Creo 12.4 本机（无会话） | `session_status(2)`，`auto` | 直连与桌面均 `-4`，采纳直连并记录 `desktop_retry`，证明链路可用 |
| Creo 12.4 本机（有会话） | `direct` / `desktop` 各一次 | 两条路径均 `toolkit_code=0` |

## 实现与证据

`desktop_worker.py`（新增）、`bridge.py`（`worker_launch_mode`、`_desktop_probe`、`session_status`）、`config.example.json`、`docs/INSTALL.md`。本机三条实测见[本次证据](../validation/STARTUP-HEADLESS-2026-11-13.md#bug-127)；报告宿主的 `-4` 是否因此清零仍未验证，BUG-005 保持原状。
