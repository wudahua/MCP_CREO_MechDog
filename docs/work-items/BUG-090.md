## 问题或目标

**已证现象（外部环境，2026-10-29 与 2026-10-30 两次）**：在 Windows x64 / Creo Parametric 10.0.0.0 / 同版本 Toolkit SDK / VS2022 BuildTools 14.44.35207 / Python 3.13 环境下，`bridge.py build` 编译失败：

```
native/advanced.cpp(487): error C3861: "ProSmtPartThicknessValueGet": 找不到标识符
native/advanced.cpp(487): error C2677: "==" : 没有找到接受"ProErrors"类型的全局运算符(级联错误)
```

报告方称在 Creo 10 SDK 全目录 `.h` 中检索无该声明，且无 `ProSmtPart.h`、无可用的版本条件宏；并称对 0.8.2 相对 0.7.2 的 5 个原生改动文件做 `Pro*` 调用与 SDK 声明的系统比对，**缺失的只有这一个 API**。

**本机当前源码状态（2026-10-30 静态核对，非编译证据）**：`native/advanced.cpp` 仍**无条件**引用 `ProSmtPartThicknessValueGet`（本轮核对命中 3 处：零件级板厚同步读值、`flange_relief_record` 的信息性字段读取），未见 `#ifdef` 守卫；`tools/generate_constants.py` 的探测仍限于常量，报告方建议的函数声明探测（`MECHDOG_HAS_ProSmtPartThicknessValueGet` 一类）未落地。因此**当前 0.9.0 源码在 Creo 10 SDK 上仍会命中同一编译阻断**，但本机没有 Creo 10 SDK，**未取得编译实测**。（本段为 N00 登记时点快照；N01 已于同日实现门控与回退，现状以文末 2026-10-30 N01 记录为准。）

**本机处置差异（重要）**：报告方在自己的机器上给 `native/advanced.cpp` 打了本地补丁（+7 行 `#ifdef MECHDOG_HAS_ProSmtPartThicknessValueGet`，`#else` 分支 `thickness_known = false` 走既有 null 降级路径）后才编译通过。该补丁**只存在于报告方本机**，不是上游状态；其 worker 指纹（`c703dee5…` / `8a44444f…`）含本地补丁，与上游官方 worker 指纹不同，属预期，不得当作本仓库证据。

**报告方已认可的口径**：Creo 12.4 下宏命中、行为逐字节一致；Creo 10 下 `part_thickness_mm` / `width_at_least_thickness` 为 `null`——但这两个字段当时正被作者在 BUG-032 记为「不可信」（1 mm 薄板读出 3.71 mm 零件级默认板厚），因此报告方判断退化不损失可用信息。**该判断的前提在本轮已部分失效**：0.9.0 已把零件级板厚改为由 `SMT_THICKNESS` 参数驱动并在实机证明读数由 3.71 变为 1.0，板厚读数不再「本就不可信」；因此「降级为 null 不损失信息」这一结论**不能直接沿用**，须在本卡重新核对降级语义。

**目标**：让 0.9.0 源码在缺少该声明的 SDK 上不再无条件引用不存在的 API，同时**不因降级而使未校验的板厚静默成功**——0.9.0 的首壁板厚硬校验与 T03 真实回读契约必须保留。
