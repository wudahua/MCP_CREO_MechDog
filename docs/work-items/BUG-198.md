# BUG-198 Windows JSON 原子替换把瞬时 WinError 5 误判为永久 ACL 失败

分类：**已有修复但待验收**。缺陷，P1，目标版本 0.49.0。

来源为 [0.48.3 反馈](../validation/feedback-0.47.1-0.48.3-2026-11-27/SOURCE_MANIFEST.json) `v0483-json-replace-winerror5.md`（关联 `DEV-066` 第 5 条）。在 Windows 上运行 `tools/test_unit.py` 时，`bridge.write_json` / `_replace_json` 遇到瞬时 WinError 5（外部索引器/杀软句柄锁定 `.tmp` 或目标文件）在 `attempts=1` 即放弃重试，导致测试体及 `TemporaryDirectory` 清理报错。

## 根因与设计边界

1. `_replace_json` 遇到 `winerror == 5` 时仅检查 `path.stat().st_file_attributes` 并在 `except OSError` 时直接设为 `retryable = False`；首次创建文件（目标不存在）或 `stat` 本身被瞬时锁拒绝时都会误判为永久只读/ACL 失败，同时未检查 `temp` 的只读属性。
2. `JSON_REPLACE_TIMEOUT = 1.0` s 与 `JSON_REPLACE_MAX_ATTEMPTS = 25` 对后台扫描瞬时锁偏紧；清理 `.tmp` 文件也未对瞬时 WinError 5/32/33 重试。
3. `src/creo_mechdog/lock_files.py` 的 `open_lock_file` 保持现有一次性 `OPEN_EXISTING` / `CREATE_NEW` 语义不变，避免破坏已有 ACL 错误不降级契约（`tests/unit/test_lock_files.py`）。

## 范围

- `src/creo_mechdog/bridge.py`：新增 `_is_readonly_file`（仅在 `stat` 成功且确含 `FILE_ATTRIBUTE_READONLY` 时返回 `True`，并覆盖 `path` 与 `temp`）；提高 `JSON_REPLACE_TIMEOUT = 4.0` 与 `JSON_REPLACE_MAX_ATTEMPTS = 100`；新增 `_unlink_with_retry` 供 `write_json` 与 `_write_stamp_text` 使用，`_write_stamp_text` 改用 `_replace_json`。
- `src/creo_mechdog/panel_session_guard.py`：`reserve` / `retire` 改用带重试的原子替换与清理。

## 验收

- 单元测试覆盖：`stat()` 抛出 `FileNotFoundError` 或瞬时 `PermissionError` 时 WinError 5 正确重试；真实只读目标或只读临时文件在 `attempts=1` 立即失败；清理 `.tmp` 瞬时 WinError 5 重试成功。
- `tools/dev_check.py --unit-timeout-seconds 1800` 全量离线门禁通过（`checked_source_sha256=f752927fd9940930b898d2aca34e497d0aa73f4f44cab4d1e8ad1279ffecc0df`；`lint_findings=0`, `unformatted_files=0`；4592 单测 `OK (skipped=6)`；`test_update_check` / `test_model_reconciliation` / `test_mcp` 通过；`Bug198JsonReplaceTests` 与 `RegistryIO` 全过）。
- 未测范围：真实 Windows Search 索引器/杀软并发文件锁现场与 WorkBuddy 黑盒验收。
