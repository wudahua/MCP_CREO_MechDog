# BUG-199 runner 随 stdio 断开即死、cancel_job 杀错 PID、死亡无出口与面板锁死循环

分类：**已有修复但待验收**。缺陷，P0，目标版本 0.49.0。

来源为 [0.47.1 反馈](../validation/feedback-0.47.1-0.48.3-2026-11-27/SOURCE_MANIFEST.json) `v0471-runner-disconnect-panel-lock.md` §1–§2、§6.6（问题 A、B、K、L）。

## 范围

- `src/creo_mechdog/bridge.py` & `src/creo_mechdog/desktop_worker.py`：
  - 准确探测进程是否处于 Windows Job Object（`IsProcessInJob` / `QueryInformationJobObject`），避免 `spawn_detached_runner` 误报 `runner_detached_from_job=true`。
  - 在允许的交互式桌面下通过 `desktop_worker.launch_detached_command` 启动真正脱离客户端 Job Object 的 `run-job`（支持 `--log-file` 重定向 `runner.log`），并在 `_run_job_dispatch` 启动时立即刷新真实 `runner_pid` 到 `channel_claim`、`worker_started=False` 占位及异常兜底终态落盘；若宿主拒绝脱离，在 `manifest.message` 明确提示保持会话连接。
  - 所有 `run-job` 启动点（`bridge.create_job`、`adoption.py`、`file_adoption.py`、`open_file.py`、`reconciliation.py`、`session_erase.py`）统一经由 `spawn_detached_runner`。
  - `bridge.get_job` 为 `queued`/`running` 作业补充只读 `owner_liveness` 诊断并在 `compact_job` 透传。
- `src/creo_mechdog/generic_bridge.py`：
  - `cancel_job` 按 `runner_identity.pid` 优先定位并终止（并清理遗留 `native_worker`），映射 `taskkill` `returncode=128`（进程不存在），在所有记录所有者已死亡时允许将 `queued`/`running` 作业推进至终态并释放 `pending_job` / channel claim；`_terminate_process_tree` 以字节读取并用 `mbcs/utf-8(errors="replace")` 安全解码。
  - `submit()` 在 `ToolkitBusy(pending_job)` 中附加 `blocking_job_status` / `blocking_runner_alive` 与死作业清理指引。
- `src/creo_mechdog/reconciliation.py` & `src/creo_mechdog/creo_startup.py`：
  - `_owners()` 补充 `worker_started is None` 且处于启动前阶段、无任何原生产物、且 `runner.stopped` 时的判定，不再逼迫重启 Windows。
  - `confirm_panel_closed` 放宽为「面板作业已达终态，或该作业已记录 `runner_identity` 且所有已记录所有者均 `stopped=true`」，打破会话锁死循环。
  - `CreoStartup._run()` 显式捕获 `PanelSessionLocked` 并单独分类上报，不再误归类为 `configuration_error`。
- `native/panel_run.h`：
  - 在提交 Done 后立即记录 `PANEL_DONE_SUBMITTED`；等待 `entering == 0` 超时后记录 `PANEL_EXIT_WAIT_TIMEOUT`，并对 Creo 进程执行只读有界 `EnumWindows` 模态框观测，写入 `PANEL_MODAL_WINDOWS` 与结果 `modal_dialogs_observed`。

## 验收

- 单元测试覆盖 Job Object 判定、Explorer 脱离回退、无效桌面 HWND (`tid==0`) 防护、`cancel_job` PID/128 处理、`_owners()` 启动前死 runner 判定、`confirm_panel_closed` 死所有者解锁、`PanelSessionLocked` 启动分类与 `owner_liveness`。
- `tools/dev_check.py --unit-timeout-seconds 1800` 通过（4592 单测 `OK (skipped=6)`，`lint_findings=0`, `unformatted_files=0`）。
- 本机 Creo 10.0.0.0（`release_numeric=42`、`worker_sha256=73354279ce7016b3573f37a50213dc55439078d6f40dc7c96b83f0a0b07073c1`）实测：隔离 `WinSta0\exebox-*` Job Object 下真实 `mcp` SDK `stdio_client` 如实上报 `runner_detached_from_job=false` 与保持连接提示（保活作业 `3b515eb80f7b4b65a919d1ed91c344c1` 推进至 `succeeded/verified`）；立即断开后失联作业 `5ba519a99d06490a9f962823e026141b` 被 `owner_liveness.all_recorded_owners_dead=true` 识别并经 `cancel_job` (`returncode=128`, `reason="process_not_found"`) 清理 `pending_job` 与通道锁。
- 未测范围：`WinSta0\Default` 交互式 Explorer 下 `runner_detached_from_job=true` 跨客户断连实机存活、`native/panel_run.h` 模态框实机卡住现场、Creo 9 / 12.4 与 WorkBuddy 黑盒验收。
