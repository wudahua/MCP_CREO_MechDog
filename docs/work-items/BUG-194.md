# BUG-194：`auto` 求解器将 B 样条/圆弧草图改判 `coordinates` 致 `1e-5 mm` 硬拒回归

类型：缺陷。优先级：P1。

分类：**已有修复但待验收**。0.47.0 交付 `auto` 求解器回归修复与自助出口提示；Creo 10 实机与 4548 项单测通过。 [发布记录](../validation/RELEASE-0.47.0.md)

## 来源与现象

2026-11-26 外部 0.45.1 / Creo 10.0.0.0 反馈 §2、§7、§14.1–14.2：

- `BUG-108`（0.45.0）将 `profile_dimensioning_choice` 改为对含 `b_spline` 与 `arc` 的无约束草图默认走 `coordinates`（`unconstrained_coordinate_profile`）。
- Creo 自身在坐标标注下会把 B 样条控制点与圆弧 `center_radius_angles` 量化到 `1e-4`–`1e-3 mm` 量级，导致 `arm7`（`a7_s3`、`max_deviation_mm=0.00120867`）与 `rotor`（`rotor_s1`、`max_deviation_mm=9.8745877e-05`）在 `0.43.0` 成功、`0.45.1` 默认被 `1e-5 mm` 硬拒。
- `capabilities.py` 仍声明 `spline/ellipse use autodim`，与代码行为矛盾；失败回执也未提示 `dimensioning="autodim"` 或 `geometry_tolerance_mm` 自助出口。

## 范围与验收

1. `native/sketch_coordinates.cpp`：`dimensioning="auto"` 时仅对 `line`/`centerline`/`rectangle`/`polyline`/`circle` 默认走 `coordinates`，含 `b_spline`/`arc`/`spline`/`ellipse` 恢复路由到 `autodim`（`unsupported_coordinate_entity`）；显式 `dimensioning="coordinates"` 仍保留对精确 `b_spline`/`arc` 的支持。
2. `enforce_geometry_deviation` 在 `coordinates` 拒绝消息中追加自助出口提示（`dimensioning="autodim"` 与 `geometry_tolerance_mm=<cap>`）。
3. 同步更新 `src/creo_mechdog/capabilities.py` 的 `sketch.limits` 说明。
4. 补充单元测试并编译原生执行器，在本机 Creo 10 上复现并验证 `b_spline`、`arc` 默认 `auto` 通过及 `circle`（`BUG-108`）仍走 `coordinates`。
