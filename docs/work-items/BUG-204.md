# BUG-204 Creo 10 放样回调加载与状态提示一致性

分类：**已有修复但待验收**。缺陷，P1，目标版本 `0.50.0`。基线为 v0.49.0 发布后回填提交 `949c7f6b`（衔接 `BUG-193` / `BUG-201`）。

来源：[0.48.3 反馈原件](../validation/feedback-0.48.3-2026-11-28/originals/recovery-and-modeling.md)（P3）与 [weld-and-loft.md](../validation/feedback-0.48.3-2026-11-28/originals/weld-and-loft.md)。

## 范围

- `creo_startup_status` 与 `creo_session_status` 在已连接 Toolkit 会话时补充非阻塞 `callback_advisory`（基于部署与已观测状态汇总，不阻塞 9 s 原生探针），消除 `ready=connected` 与 `loft.runtime_ready=false` 的语义冲突。
- `creo_callback_status` 与 `blend_callback` 在非 `ready` 态输出 `affected_operations`、`unaffected_alternatives`（标明 `creo_new_loft_part` 为 `new_part_only`）及可执行 `recovery_steps`（指明 `delay_start=true`、Auxiliary Applications 注册/Start 与复查步骤）。

## 验收

- **实机验证（2026-11-28 Creo 10.0.0.0 重启前后冷启动）**：
  - 根因定位：Creo `Common Files/text/config.pro` 已持久化配置 `protkdat D:\my\MCP_CREO_MechDog\build\blend_callback_protk.dat`，注册本身有效；`blend_callback_protk.dat` 配置了 `delay_start true`，导致每次冷启动 Creo 仅注册未激活。
  - 冷启动后实测一致：`creo_startup_status` 与 `creo_session_status` 均输出 `callback_advisory`（`ready_for_direct_loft=false`）；`creo_callback_status` 返回 `readiness="not_loaded"`、`reason="recorded_application_not_active"` 及 `affected_operations`/`unaffected_alternatives`/`recovery_steps`；`creo_capabilities(detail="compact")` 同步反映 `loft`/`surface_loft` `runtime_ready=false`；`creo_loft` 提交前直接拦截（`BLEND_CALLBACK_SETUP_REQUIRED`）。
- 单测：`tests/unit/test_v0500_feedback_0483.py::Bug204CallbackGuidanceTests`、`tests/unit/test_blend_callback.py` 通过。
- 未测范围：隔离执行桌面（`EnumWindows` 零窗口）下无法自动点击 Creo UI 启动回调，因此 `readiness="ready"` 态下的最小 `creo_loft` 创建、Creo 9 / 12.4 与 WorkBuddy 黑盒单列待验（已有通用交互路径另见 `BUG-193` 0.46.1/0.46.0 记录）。
