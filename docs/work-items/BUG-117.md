# BUG-117：feature_state 的 targets 形态报错不可读，级联自动基准面强制两轮往返

## 当前摘要（2026-11-10）

分类：**已有修复但待验收**。类型：缺陷（可用性）。优先级：P2。

来源：2026-11-10 下载目录 `0.19.3` 第一批反馈报告 P4（Creo 10.0.0.0 / 0.19.3），并在第三份报告的真机复测中**跨场景再次复现**。映射见 [归档 MAPPING](../validation/feedback-0.19.3-2026-11-10/MAPPING.md)。

结论：报错可读性与重提提示已离线修复；**「自动创建的支撑基准面自动纳入删除」未实现**，因此「每个删除都要两轮往返」这一半仍开放。

剩余范围：

- 决定是否为 `feature_state` 增加 `include_auto_datums` 或等价语义（需公开契约冻结：字段名、默认值、误删风险、回执字段）。
- 实现前先在实机确认：自动基准面被显式删除与随草图删除的效果是否一致（体积、特征树、revision、保存重载）。

## 现象

**级联依赖无标签**：删除 4 个错误特征 + 4 个草图被拒绝，依赖列表里是 MCP 创建草图时自动生成的 `no_name` 基准面：

```
feature_state targets do not cover every affected dependency; Creo also deleted these features;
list them explicitly (no automatic cascade): [{"feature_id":6823,"label":null,"name":"no_name",
"type_name":"datum_plane"}, ...共 8 个]
```

调用方无法预先知道这些 ID，只能从错误信息抄 8 个整数再重提。

**targets 形态报错暴露内部校验器**：按直觉传 `{"kind":"feature","label":"xxx"}` 得到：

```
operations[0].targets[0].function-wrap[_explain_label_pattern()]: Input should be a valid string
operations[0].targets[0].int: Input should be a valid integer
```

既未说明合法形态（裸 label 字符串或整数 ID 的**数组**），又暴露内部校验器名。

## 本轮处理（2026-11-10，离线）

- `schema_base` 外的 `_normalize_feature_target`（`src/creo_mechdog/schema.py`）：对象形式在联合类型之前被单独拒绝，报错为单条调用方文本，含合法示例 `["door_upper_neg", 6823]`，不再出现 `function-wrap[...]` 或 `_explain_label_pattern`。
- `src/creo_mechdog/feature_state.py` 与 `native/feature_state.cpp`：依赖列表文本追加「把上面的 feature_id 加到 targets 后按同一 action 重提；自动创建的支撑基准面无标签，其 ID 只在这里出现」。
- 依赖列表本身仍是机器可读 JSON（这点报告方认可，保留）。
- 回归：`tests/unit/test_feedback_0193_contract.py`（对象拒绝文案、无内部符号、裸数组仍通过、两处提示存在）、`tests/unit/test_t08_feature_state.py` 全绿。
