# BUG-202 面板锁恢复指引与无会话恢复准入

分类：**已有修复但待验收**。缺陷，P1，目标版本 `0.50.0`。基线为 v0.49.0 发布后回填提交 `949c7f6b`（衔接 `BUG-199` / `BUG-171`）。

来源：[0.48.3 反馈原件](../validation/feedback-0.48.3-2026-11-28/originals/recovery-and-modeling.md)（P1、P2）。

## 验收

- **实机验证（2026-11-28 Creo 10.0.0.0）**：
  - 面板锁场景：从未知 `model_id` 起点调用 `creo_startup_status` 与 `creo_session_status`，均返回 `panel_session_locked`、`model_id="835c261b854b476a971401a5373d40be"` 及先 `inspect` 后 `confirm_panel_closed` 步骤；活动持有者（存活 PID）运行期间 `confirm_panel_closed.available=false` 且 `apply` 被拒，持有者退出且作业进入终态后经 `inspect → confirm_panel_closed=true` 成功退役保护（`state="retired"`，模型原 `revision`/`status` 保持）。
  - Creo 明确未运行恢复：在无 `xtop.exe` 且零 `creo_worker.exe` 下调用 `restore_baseline`（`live=true`）与 `accept_live`，分别在启动任何恢复 worker 前被拒（`restore_baseline` 返回 `status="rejected"`、`reason="no_creo_session"`、`failure_phase="before_native"`、`worker_started=false`；`accept_live` 因无活体证据被拒），重新 `inspect` 验证原 `status`、`revision` 与 `pending_job` 完整保留。
- 回归与单测：`tests/unit/test_feedback0483_0471_fixes.py`、`tests/unit/test_reconciliation.py`、`tests/test_creo_startup.py` 全部通过。
- 未测范围：Creo 9 / 12.4、真实交互桌面并发多窗口卡死及外部 WorkBuddy 黑盒验收。
