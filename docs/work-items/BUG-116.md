# BUG-116：draft 中性面示例误导，且引用解析失败不指名字段

## 当前摘要（2026-11-10）

分类：**已有修复但待验收**。类型：缺陷。优先级：P1。

来源：2026-11-10 下载目录 `0.19.3` 第一批反馈（Creo 10.0.0.0 / 0.19.3，378 特征 `frigate_txt_rebuild`），报告 P1 与 P5。原件与 MAPPING 见 [归档](../validation/feedback-0.19.3-2026-11-10/MAPPING.md)。

结论：离线修复已交付（示例、语法说明、原生命名与候选数）。**实机文案与建模效果未验证**；报告方「约 2 分钟再生后才失败」的代价是否下降未实测。

剩余范围：

- 在 Creo 12.4 与 Creo 10 上各复现一次「同高度多张平行基准面」的 draft，核对回执含 `failed_reference`、候选数与候选 ID，并确认几何与 `effective_flip` 正确。
- 报告方建议的「提交前预解析并区分两种引用」只在原生解析期实现；Python 侧无几何访问，未做提前判定。

## 现象（报告方原文要点）

`creo_draft` 提交 `neutral_plane = {kind:'datum_plane',axis:'z',offset:350}`，排队约 2 分钟后失败：

```
Plane reference must identify exactly one surface; inspect the model and use a surface ID
```

改成 `{kind:'plane',normal:[0,0,1],offset:350}` 立即成功。报告方指出三点：

1. `creo_capabilities` 的 `references.creo_draft` 示例恰是 `datum_plane` 形式，只在空模型成立。
2. 两种形式的语义差异（基准面特征集合 vs 几何面位置集合）文档未说明。
3. 错误信息不指名是 `neutral_plane` 还是 `surfaces[]`，也不提示替代形式。

## 本轮处理（2026-11-10，离线）

- `src/creo_mechdog/references.py`：`creo_draft.neutral_plane` 示例改为 `{"kind":"plane","normal":[0,0,1],"offset":0}`；新增 `syntax.plane_by_position` 说明 `plane` 按几何位置解析、`datum_plane` 按 axis+offset 且候选必须唯一、位置歧义时改用显式 ID。示例键保持只含真实参数，避免污染 `DraftOp` 的严格模型。
- `native/generic.cpp`：平面引用多候选时，错误信息带候选数、候选 ID 列表（最多全部）与推荐形式；保留原有拒绝语义，不自动挑一张面。
- `native/advanced.cpp`：新增 `resolve_field()`，draft 的 `surfaces[]`、`neutral_plane`、`pull_direction` 失败时统一输出 `failed_reference field=<参数> value=<传入引用> detail=<原生原因>`；`pull_direction` 为 `null` 时按文档默认取中性面法向（原实现会把 null 当引用解析）。
- `docs/REFERENCE_SYNTAX.md`：平面筛选器一节补两种形式取舍，`draft.surfaces/neutral_plane/pull_direction` 行同步。
- 回归：`tests/unit/test_feedback_0193_contract.py`（示例形状、语法说明、示例仍可校验）、`tests/unit/test_reference_contract.py` 全绿。
