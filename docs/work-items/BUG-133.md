# BUG-133：显式旋转矩阵容差在 Python 与原生端不一致

分类：**已交付 0.35.4**（2026-11-21 按实机实测边界把准入收紧为 `1e-7`，离线全量门禁通过）。

类型：缺陷。优先级：P1。状态：已交付 0.35.4（准入已收紧为 `1e-7`，六位小数矩阵在提交前被拒绝；2026-11-21 实机证据见下）。目标版本：0.35.4（已交付）。

来源：[DEV-092](DEV-092.md) 对 Creo 13.4 / MCP 0.26.0 装配评估的离线核对。报告建议为六位小数矩阵传 `rotation_tolerance=1e-5`，本次发现该建议只通过 Python 准入，原生仍会拒绝。

## 现象与原因

- `src/creo_mechdog/schema.py` 的 `AssemblyPose.matrix_tolerance_valid` 按调用方的有效容差校验。
- `native/assembly_pose.h` 的 `assembly_rigid_transform` 调用 `assembly_rotation_admission` 后，仍以固定 `assembly_admission_tolerance() == 1e-6` 拒绝；原生代码没有读取 `rotation_tolerance`。
- 创建组件、重定位和失败回执重算共用该 helper，因此存在 Python 已接收、原生再拒绝的确定性分歧。尚未连接 Creo 重现公开工具终态，不据此断言 Creo 内核会接受放宽后的输入。

最小独立输入（合成的 28° 六位小数算例，**不是**报告缺失的 P03 原始矩阵）：

```json
{"op":"component_placement","component":"probe","rotation_matrix":[[0.882948,0.469472,0],[-0.469472,0.882948,0],[0,0,1]],"rotation_tolerance":0.00001}
```

`max |R R^T-I| = 1.1294880000178864e-6`。本次 Python 准入通过且矩阵保持原值；相同矩阵在默认 `1e-6` 下拒绝，报错显示 `1.129488e-06`。本次 SDK 无关 C++ probe 调用生产 helper，在同样显式 `1e-5` 下仍拒绝，已确认跨层分歧；构建/运行均退出 0，其中运行 0 代表捕获预期拒绝，并非修复通过。实施与实机范围见 [处理计划](../archive/superpowers/plans/2026-11-19-dev092-creo13-assembly.md)。

## 范围与验收

1. 统一 Python、原生 helper、直接原生输入校验和回执的有效容差；默认保持 `1e-6`，不自动转置、重正交或修改输入数值。
2. **实施前待冻结的边界**：当前 Python 只要求容差为正且有限，超大值可能放行反射/缩放。需先定义允许上限或独立刚体判定，再同步两层；该决策可能收紧现有 Python 输入范围，要明确兼容性影响，不能仅让原生照搬任意正数。回归覆盖创建/重定位、缺省/显式容差、布尔/非有限/非正数、超限非正交、反射及默认行为；接收与报告使用相同规则。
3. 在 SDK 无关的 `tests/native/test_assembly_pose.cpp` 增加失败用例，使用 `tools/test_assembly_pose.py` 验证生产 helper，不加载 Toolkit。
4. 修改后运行专项及 `tools/dev_check.py --work-item BUG-133`。原生执行器构建和 Creo 几何/保存重载验收须用户当次明确确认。若内核仍拒绝，准确报告阶段/API/原始错误，不自动修复矩阵或宣称该精度可建模。

## 冻结的容差契约（2026-11-19，实施前决策）

- 默认准入容差保持 `1e-6`，为唯一公开值；`rotation_tolerance` 省略或 null 时取该值。
- 显式容差允许范围收紧为 `0 < t ≤ 1e-3`（`MAX_ADMISSION_TOLERANCE` / `assembly_max_admission_tolerance`）。依据：准入条件同时要求 `max |R*Rᵀ−I| ≤ t` 与 `|det−1| ≤ t`；反射的 `|det−1| = 2`、缩放基的偏差远大于 `1e-3`，因此上限以内的任何值都不会把非刚体变换放进通道，而 `1e-3` 已是上报六位小数算例（`1.1e-6`）的百倍余量。上限之外不再描述“四舍五入”，且会让原本被拒的反射/缩放通过。
- 兼容性影响：此前 Python 只要求正有限（`Positive` 上限 100000），`rotation_tolerance > 1e-3` 是被接受的；现在两层一致拒绝，属明确收紧。没有既有实机调用依赖该区间，拒绝时给出可操作的原文。
- 只对显式 `rotation_matrix` 生效；Euler 输入带 `rotation_tolerance` 直接拒绝，避免无效字段静默生效。
- 两层同值：Python `validate_tolerance` 与原生 `assembly_tolerance_from_json` 使用同一上下界；原生成功回执发布 `rotation_tolerance`（有效值）与 `input_rotation_convention`，失败回显发布 `matrix_convention`/`admission_tolerance` 并按同一门槛测量。

失败路径的拒绝项（Python 层，未提交作业）：默认容差下的六位小数矩阵、`det=-1` 反射矩阵、`rotation_tolerance=1e-2` 均按冻结契约拒绝。

结论（证据范围）：

- Python 与原生 helper 的准入已一致（A/B/E 通过，拒绝项按同一契约生效），原缺陷（两层容差分歧）在实机路径上不再出现。
- **内核边界仍拒绝**：同样的六位小数矩阵只要残差 `1.1294880000178864e-6` 不为 0，`ProAsmcompAssemble` 与 `ProAsmcompPositionSet` 都在 Creo 10 返回 `-2`。因此 `rotation_tolerance=1e-5` 目前只放宽了准入，不能把该精度变成可建模；六位小数矩阵的实机放置不可用，精确正交矩阵可用。
- 未自动转置/重正交/修改输入，也未宣称该精度可建模；失败作业按既有规则回滚。当时的两个待决策项是“收紧准入为精确正交”或“保留 `1e-3` 契约并只改失败诊断”。2026-11-21 已按前者实施：准入收紧到实测 `1e-7`，见下一节。

## 2026-11-21 产品决策与实施：准入收紧为实测 `1e-7`（随 0.35.4 交付）

在六位小数算例外补了精度阶梯与扰动扫描，得到内核接受区间：

| 最大残差 `max |R*R^T-I|` | 用例 | 内核结果 |
| --- | --- | --- |
| `4.5e-10`、`7.664e-9`、`4.7552320081578614e-8` | 9/8/7 位小数 28° 矩阵 | 成功放置，保存重载 true |
| `2.241e-7`、`4.890e-7` | 单位矩阵扰动 `1e-7` / `2.5e-7` | 失败，`-2` |
| `1.1294880000178864e-6` | 6 位小数 28°（C/D 例） | 失败，`ProAsmcompAssemble`/`ProAsmcompPositionSet` 均 `-2` |

边界落在 `4.7552320081578614e-8` 与 `2.241e-7` 之间。`rotation_tolerance=1e-5` 只放宽 Python/原生准入，不能改变内核判断，因此保留大容差只会把必败作业送进执行器。决策：**把准入收紧到内核可接受范围**，而不是继续承诺“显式容差可救回六位小数”。

- `ADMISSION_TOLERANCE = 1e-7`、`MAX_ADMISSION_TOLERANCE = 1e-7`；Python `validate_tolerance` 与原生 `assembly_tolerance_from_json` 同步，缺省与上限相同。
- 显式容差现在只能严格收紧；六位小数矩阵在 `validate_operations`/原生入口即被拒绝，报错给出残差并说明内核在 `1e-7` 以上返回 `-2`，不再建议用更大容差。
- 仍不自动转置、不正交化、不修改输入；`1e-9` 继续只用于 `strict`/`near_orthonormal` 分类。
- 同步修改：`src/creo_mechdog/rotation_admission.py`、`native/assembly_pose.h`、`schema.py`、`capabilities.py`、`server.py`；回归覆盖 `tests/unit/test_rotation_admission.py`、`test_assembly_matrix_poses.py`、`test_assembly_pose.py`、`test_assembly_matrix_rollback.py`、`test_failed_operation_context.py` 与 `tests/native/test_assembly_pose.cpp`。
- 影响：此前依赖 `1e-5`/`1e-3` 放行六位小数矩阵的调用现在会在提交前失败；改用精确正交矩阵或从角度重建即可通过。该边界只对本次 Creo 10.0.0.0 / release 42 有实机证据，其他版本未测。
- 验证：`bridge.py build` 退出 0；`tools/test_assembly_pose.py` `success=true`（I032 拒绝、30° 接受、七位小数原样回显）；`tools/dev_check.py` 全量 4299 项通过（6 跳过），Ruff 与 clang-format 通过。
- 未做：发布、其他 Creo 版本、WorkBuddy 黑盒；本次不重新宣称六位小数矩阵可建模。
