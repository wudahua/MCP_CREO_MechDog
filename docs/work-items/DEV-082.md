# DEV-082：缺头 SDK 的聚合编译契约与跨 TU 符号可见性

## 当前摘要（2026-11-10）

分类：**开发中**。类型：工程/测试闸门。优先级：P1。

来源：2026-11-10 下载目录 `0.19.3` 第四份报告（Creo 10.0.0.0 升级核验）P1-1 与 P1-2。映射见 [归档 MAPPING](../validation/feedback-0.19.3-2026-11-10/MAPPING.md)。与 [DEV-080](DEV-080.md) H01（抽 `native/element_tree_json.h`）是同一根因的两段：本卡先消除编译阻断并加闸门，H01 才是正解。

结论：最小门控与静态聚合契约已交付（离线 + 本机 Creo 12.4 SDK 编译）。**真实 Creo 10 SDK 整包编译未验证**。

剩余范围：

- H01 正解：抽 `native/element_tree_json.h`，让 `SURFACE_LOFT_TREE_SAMPLE_LIMIT` / `loft_element_json()` / `loft_tree_json()` 移出 `#if`，SDK 无关部分在缺头分支仍可见；把 `SDK_OPTIONAL_HEADERS` / `MECHDOG_HAS_*` 做成生成器与手写 TU 共享的单一真值源。
- 真实 Creo 10 SDK 上跑一次 `bridge.py build`，确认 `C1083`/`C2065`/`C3861` 全为 0（本机无该 SDK，本轮未验）。

## 现象（报告方原文要点）

0.19.2 起 `native/surface_loft.cpp` 用 `__has_include(<Probbl.h>)` 定义 `MECHDOG_HAS_PROBBL_HEADER`，`C1083` 消失；但同一个 `#if` 把 `SURFACE_LOFT_TREE_SAMPLE_LIMIT`、`loft_element_json()`、`loft_tree_json()` 一起藏起来，而 `native/surface_boundary_fill.cpp` 无门控地复用它们与 `PRO_E_DTM_SRF_TYPE_BND_BLEND`，缺头 SDK 上整包编译得到：

```
native\surface_boundary_fill.cpp(115): error C2065: 'SURFACE_LOFT_TREE_SAMPLE_LIMIT': undeclared identifier
native\surface_boundary_fill.cpp(118): error C3861: 'loft_element_json': identifier not found
native\surface_boundary_fill.cpp(158): error C2065: 'PRO_E_DTM_SRF_TYPE_BND_BLEND': undeclared identifier
```

同时 0.19.3 新增的两项头门控契约测试 8/8 通过：它们只扫 `#include` 行、只编译 `using J = int; #include "surface_loft.cpp"` 的单 TU，不覆盖聚合编译。

## 本轮处理（2026-11-10）

1. **门控修复**（`native/surface_boundary_fill.cpp`）：在 include 之后加 `#if MECHDOG_HAS_PROBBL_HEADER`，把整个 boundary-fill 主体（含以 `ProCurve.h` 为基础的 helper）包进该分支；`#else` 分支只保留 `generic_surface_boundary_fill` 的 stub，抛
   `SURFACE_BOUNDARY_FILL_SDK_UNAVAILABLE: surface_boundary_fill requires Probbl.h; ... No feature was created`。
   文件顶部另加 `MECHDOG_HAS_PROBBL_HEADER` 的兜底定义，使该 TU 即使脱离 `surface_loft.cpp` 单独包含也能自洽（与 `surface_loft.cpp` 的 `#ifndef` 语义一致，不覆盖已有宏）。
2. **聚合编译契约**（`tests/unit/test_native_aggregate_compile.py`，4 项）：
   - 从 `surface_loft.cpp` 收集「只在门控分支声明」的 `static` 符号；
   - 扫描其它 `native/*.cpp`，要求这些符号的引用都处于同一门控分支内（跨 TU 符号可见性）；
   - 断言 `surface_boundary_fill.cpp` 有门控、有 stub、宏区闭合；
   - 所有 `native/*.cpp` 的门控区必须配平。
   该测试会剥离 `//` 与 `/* */` 注释，避免注释文本造成误报。
3. **可检出性自证**：把 `surface_boundary_fill.cpp` 的门控行删掉放入临时副本，测试函数报出
   `SURFACE_LOFT_TREE_SAMPLE_LIMIT`（3 处）与 `loft_element_json`（1 处）未门控引用，与报告方 4×`C2065`+1×`C3861` 的形态一致；验证后删除临时副本。
