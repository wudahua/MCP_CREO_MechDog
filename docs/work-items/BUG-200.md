# BUG-200 adopt / open_file / session 工具 worker 115 s 硬编码超时致大模型锁死

分类：**已有修复但待验收**。缺陷，P1，目标版本 0.49.0。

来源为 [0.47.1 反馈](../validation/feedback-0.47.1-0.48.3-2026-11-27/SOURCE_MANIFEST.json) `v0471-runner-disconnect-panel-lock.md` §3.5（问题 C2）。

## 范围

- `src/creo_mechdog/bridge.py` & `config.example.json`：新增 `utility_worker_timeout_seconds()`（默认 300 s，受 `config.json['utility_worker_timeout_seconds']` 与可选入参 `timeout_seconds` 控制，范围 30–3600 s，并依据 `file_size_bytes` / `feature_count` 自动抬高自适应下限）；将 `utility_worker_timeout_seconds` 纳入 `build_native()` 缓存豁免键 `startup_keys`。
- `src/creo_mechdog/adoption.py`、`src/creo_mechdog/file_adoption.py`、`src/creo_mechdog/open_file.py`、`src/creo_mechdog/session_models.py`、`src/creo_mechdog/session_assembly.py`、`src/creo_mechdog/session_erase.py`、`src/creo_mechdog/reconciliation.py`、`src/creo_mechdog/server.py`：
  - 消除硬编码 `115` s 限制，接入 `utility_worker_timeout_seconds`；为 `creo_adopt_current_model`、`creo_adopt_file`、`creo_open_file` 增加可选 `timeout_seconds` 参数。
  - `adoption._native()` 在超时时主动终止 worker 进程树并记录 `worker_terminated_on_timeout=true` 与 `worker_pid` 证据，使 `reconcile` 无需重启 Windows 即可确认 worker 已停止并执行 `abandon_new`。
  - 同步更新 `file_adoption.lifetime_seconds()` 与 `bridge.expected_lifetime_seconds()`。

## 验收

- 单元测试覆盖自适应超时公式、参数校验、`timeout_seconds` 透传（含 `creo_open_file` / `creo_adopt_file` / `creo_adopt_current_model` 112 个工具 schema 核对）、以及 `adoption._native` 超时后终止 worker 证据输出。
- `tools/dev_check.py --unit-timeout-seconds 1800` 通过（4592 单测 `OK (skipped=6)`，`test_mcp` / `test_model_reconciliation` 通过）。
- 未测范围：约 6 MB / 589 特征级超大外部零件实机加载计时与超时强杀现场、Creo 9 / 12.4 与 WorkBuddy 黑盒验收。
