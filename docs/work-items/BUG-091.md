## 问题或目标

**报告方指出的核心问题不是披露，而是归属**：这条 P1 级故障已三次以不同面目出现（挂起 → 断连 → 挂起 + 重启自退出），但**没有一张处于「打开」状态的卡承载**——BUG-001 状态是「已关闭」，新现场被追加进一张关闭卡；BUG-085 专指客户端侧 `exit 20`，与「Creo 进程挂起」不是同一观测面。

**三次现场的既有事实（各条来源不同，不得合并为同根）**

| 时间 | 现象 | 现有归属 |
| --- | --- | --- |
| 2026-10-17 | 实机回归中 Creo 卡死 | [BUG-001](BUG-001.md)，已按用户决定关闭（根因未定） |
| 2026-10-26 | 0.6.1 验收中 `worker exit 20 / IPC 不可读` | [BUG-085](BUG-085.md)，调查中，**根因未定** |
| 2026-10-29 19:51:03 | `xtop.exe` `AppHangB1`；重启可起但**几分钟内自行退出**，只留 `pro_comm_msg`；`session_health.reason=session_identity_stale`、`connection_state=not_found_or_unreadable` | 记在 BUG-001 关闭卡、BUG-046、DEV-051、FEAT-014、0.8.4 版本说明与 [T11 §4.1](../development/DEV051-T11-ACCEPTANCE.md)，**无开放条目承载** |

**新增现象（此前两次没有）**：「重启后几分钟内自行退出，只留 `pro_comm_msg`」——前两次是连不上，这次是起不来/起来又倒。报告方指出它可能与「挂起」需要分开排查：前者是进程生命周期，后者是 RPC。

**正面信号**：`session_health`（T10，0.7.0 交付）**首次在真实事故中被使用**，并准确给出 `session_identity_stale` + `not_found_or_unreadable`——正是它设计的用途（只读、不写、不建连接）。报告方建议把它固化为「事故第一步」的标准动作。

**目标**：为这条 P1 级故障建立**一张开放条目**，串联 BUG-001 / BUG-085 / 三次现场，状态「开放—根因未定」；分现场给出时间线、同根判据、缺证清单与受控取证前置条件；把「重启后分钟级自退出」作为独立观测项列入现象清单；给出处置指引（什么条件下允许重启 Creo、什么条件下必须保现场、`session_identity_stale` 时的推荐步骤）。

**明确不做**：不产出「会话已恢复」的推断；不据同码推同根；不新增重连、重试或杀进程方案；不擅自启动、结束或重启 Creo，不清 unknown 保护，不注入故障；不实际探测 `session_status`、不新建 MCP 客户端。
