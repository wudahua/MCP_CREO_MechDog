# BUG-119：已有实体的模型上 `surface_loft` 被误判为创建实体

## 当前摘要（2026-11-12）

分类：**已交付 0.23.1**（Creo 12.4.0.0 实机验收；Creo 9/10 运行期未验）。类型：缺陷。优先级：P1。目标版本：0.23.1。

来源：`C:\Users\Administrator\Downloads\0.22.0` 反馈 P2（已有实体模型上曲面放样失败）。

结论：`native/surface_loft.cpp` 原来用 `inspection(false)["has_solid"]` 判断“本次放样是否创建了实体”，但该字段描述的是**整个模型**，模型原本就有实体时恒为 `true`，放样必然回滚。现改为比较操作前后的实体状态、带材料实体数与体积，只有本次真正新增实体材料才失败。

剩余范围：Creo 12.4.0.0 实机复现与回归；Creo 9/10 运行期未验。

## 现象

在已存在实体的零件上创建 `surface_loft`，任务返回失败，错误文本为
`surface_loft created solid material; a surface loft must not`，模型回滚；即使两张截面都是开放曲面、结果也是开放 quilt，仍然失败。

## 推测根因

原生回执把模型级 `has_solid` 当作本次操作的结果：

```cpp
if (details["has_solid"].get<bool>())
    throw std::runtime_error("surface_loft created solid material; a surface loft must not");
```

`details["has_solid"]` 来自 `inspection(false)`，与本次特征无关。

## 修复（2026-11-12）

- 在 `surface_loft` 创建前后分别读取 `has_solid`、`body_counts.with_material` 与 `mass_properties_json()` 的 `volume_mm3`。
- 只有满足任一条才判本次创建了实体材料：`has_solid` 由 false 变 true、带材料实体数增加、体积增加超过 `1e-6 mm³`。
- 回执保留 `has_solid`（操作后模型状态）并新增 `has_solid_before`/`has_solid_after`/`created_solid_material`/`material_bodies_before`/`material_bodies_after`/`volume_mm3_before`/`volume_mm3_after`。
- 失败文本带上前后状态与实体数，便于区分“原本有实体”和“本次造出实体”。
