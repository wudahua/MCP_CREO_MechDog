# BUG-125：Creo 启动不接受额外命令行参数（无法无图形启动）

## 当前摘要（2026-11-13）

分类：**已完成**。类型：缺陷。优先级：P1。目标版本：0.24.1。

来源：`C:\Users\Administrator\Downloads\0.23.1\2026-11-12-Creo13.4.0.0-MCP0.23.1-Toolkit连接-4与驱动蓝屏.md` P-08 与第 11 节建议 2。关联 [BUG-126](BUG-126.md)（无图形会话下建模窗口激活）与 [BUG-005](BUG-005.md)。

## 问题或目标

0.24.0 之前 `creo_startup.Settings` 只有 `executable`、`psf`、`auto_start`、`timeout`、`selected`，`launch_creo()` 固定以 `ShellExecute(parametric.exe, "<psf>", …)` 启动，配置里没有任何追加参数的入口。后果：

- 无法把 `-g:no_graphics`、`-i:rpc_input` 传给 `parametric.exe`，因此在旧显卡驱动触发 TDR/蓝屏的环境中，项目侧没有规避入口。
- 报告已确认写进 PSF 的 `RUN=` 行会被丢弃，复制 PSF 到其他目录还会破坏 `%CREOAPP_DIRECTORY%` 推导；Creo 13.4 配置库已移除 `win32_gdi`，不能用软件渲染替代。

## 范围

包含：`Settings.args` 从 `creo_startup_args` 读取；数组、非空字符串、禁 `\r\n\0` 校验；参数以 `list2cmdline` 拼在 PSF 之后传给 `parametric.exe`；`build_native` 的 `startup_keys` 增加该键与 `creo_worker_launch`，改启动选项不触发原生重编；`config.example.json`、`docs/INSTALL.md` 补示例。

不包含：不改 PSF；不自动判断何时应无图形；启动协调目录哈希仍只由可执行文件与 PSF 决定；无图形下的建模能力单列 [BUG-126](BUG-126.md)。
