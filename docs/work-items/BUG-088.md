# BUG-088：预览 raster 成功后输出文件缺失

日期：2026-10-28（Asia/Shanghai）。类型：缺陷。优先级：P2。状态：**待复现**。目标版本：未排期。

来源：[0.7.0 反馈 R1 N3](../validation/feedback-0.7.0-2026-10-28/2026-10-27_CREO_0.7.0_钣金增料与四壁折边仍未修复验收报告.md)；[逐章映射](../validation/feedback-0.7.0-2026-10-28/MAPPING.md)。关联 [BUG-066](BUG-066.md)，但该卡处理文件存在时的画面内容/视角失真，二者分别验收。归 [DEV-051 T08A](../development/0.7.0-FEEDBACK-TASKS-2026-10-28.md#t08a-预览输出文件缺失拟bug-088)。

## 现象与推测

报告人在 0.7.0 的四次外部建模调用中观察到两次（含全新空零件）`preview_status="failed"`、`failed_step="output_file"`、`failed_code=-4`、`bytes=-1`，此前 display 至 raster 的返回码均为 0，实际预览文件未取得。`view_matrix_matches=false` 同时出现，但与文件缺失的因果关系未证实。现有 `preview.h` 的文件大小查询失败可映射 -4；权限、句柄占用、写入时序或文件系统错误都只是待核对假说。原 request/job/native JSON 与图像未随报告交付。

## 范围与验收

T08A 先区分原生 raster 阶段与文件系统确认阶段，记录目标路径、存在性、大小、实际 `filesystem::error_code` 和原始原生码；隔离夹具覆盖写入失败、不存在、空文件、检查失败及成功。确定根因后才选择最小修复或有界文件检查重试，不重跑建模作业，也不把 raster=0 报成 written。实机阶段在单一受测源码上分别以空件、实体件和钣金件的新输出路径核对真实文件与状态，记录 job/model/revision、源码指纹和原始错误。内容是否正确归 BUG-066/T08C，不能以非空文件代替。

环境：离线 Windows x64 / C++17 / Python 3.12+；适用原生验收为本机 Creo 12.4.0.0 / 匹配 SDK，经单独指派和会话核对后执行。本次 T00 仅登记，没有复现、修复、单元、构建或 Creo 连接。

## 2026-10-28：T08A 离线定因（诊断阶段已修，原发现象未复现）

归 [DEV-051 T08A](DEV051-T08A-ACCEPTANCE.md)。分支 `codex/dev051-feedback070`，基线 `9f129c8d`；未连接 Creo，未重跑建模，`source_fingerprint=f1b021e052042906fefcb033e77e5788675e726ac0b082d04259da79bbb289c5`。

路径定位：`native/preview.h` `capture_preview()` 在 `ProRasterFileWrite` 返回 0 后立即用 `std::filesystem::file_size` 复查，失败即 `failed_step="output_file"`；修改前把**任何** `std::error_code` 都映射 `PRO_TK_E_NOT_FOUND=-4`（`ProToolkitErrors.h`），且不保留 value/category/message/存在性/大小。因此报告中的 `failed_code=-4` 不能作为“文件不存在”的证据，权限、共享冲突、路径与 I/O 失败在旧输出里完全同形。Python `normalize_preview()` 另有自造码：claimed-written 而本地复检失败时写 raster 码或 `-1`。

本次修改（仅诊断，不改截图顺序/视图矩阵/raster 语义）：原生新增独立确认阶段 `preview_confirm_file()`，输出 `file_check{stage,absolute,parent_exists,exists,is_file,size,error_code,error_category,error_message}`；`-4` 只保留给“路径确实不存在”，其他错误为 `-1` 且真实码在 `file_check`；投影透传 `file_check`、新增 `verification_error`（异常类型名）、不再自造失败码、保留原生 `failed_step`。`preview_written()` 仍要求 raster=0 且字节>0，原生成功而文件未确认一律 `failed`。

**未定因**：无原始 request/job/native JSON 与图像，也无本机复现，不判定是未生成、未落盘、被占用、权限或路径问题；按派发表未加有界复查/重试（重试会把延迟出现的文件当成稳定产物，且掩盖未定根因），留待实机取得真实 `error_code` 后单独决策。实机阶段仍需在单一受测源码上以空件/实体/钣金新输出路径核对；内容是否正确仍归 BUG-066/T08C。

**2026-10-29 实机**：用户授权后在本机 Creo 12.4.0.0 串行执行 `tools\test_t07_preview.py --live --confirm-session-usable`，exit 0，`preview_acceptance=passed`、`toolkit_serial=true`；`disk`、`disk_cut`、`disk_cut_pattern`、`explicit_jpeg_export` 四例均 `succeeded`，输出文件落盘并通过 `file_check` 确认。**原始 `raster=0 → output_file=-4` 现象本轮未复现**，因此只记“诊断可分辨 + 当前未复现”，**不据此关闭本卡**；图像内容正确性仍为 `human_review_pending`（归 T08C）。记录见 [T08A 验收卡](../development/DEV051-T08A-ACCEPTANCE.md)。

## 2026-10-30 N11 离线阶段：空件失败在本机历史作业中可复现，判别量已确定

阶段：离线材料核对 + 离线诊断，**未连接 Creo、未跑 `--live`**。依赖提交 `7198588`（DEV-052 N00），分支 `codex/dev051-feedback070`。未改 `native/preview.h` 与 `src/creo_mechdog/preview.py`，未改 `version.py`，未合 main，未发布。完整记录见 [N11 验收卡](../development/POST090-N11-PREVIEW-ACCEPTANCE-2026-10-30.md)。

**本机定因（本阶段最重要结论）**：本机 `jobs/` 历史作业中，空件预览失败**可复现且判别量唯一**——判别量是**该作业是否为“新建模型且无任何建模操作”**：

| 分组 | 作业数 | 写出 `preview.jpg` | 出现 `failed_step="output_file"` / `failed_code=-4` / `bytes=-1` |
| --- | ---: | ---: | ---: |
| 新建 + 零操作 | 330 | **0** | **46** |
| 新建 + 有操作 | 942 | 841 | **0** |

分离度 100%，无例外；与模型名、模板、体积、面数无关。关键区分事实：

1. **不是随机的 I/O 抖动**：零操作组 330/330 无一写出图像；另 284 个零操作作业连 `preview` 块都没有（`preview_code=0`、`preview_file` 有路径但文件不存在）。
2. **不是“空件失败后该会话就坏了”**：288 个模型在空件首作业之后继续带操作作业，其中 786 个后续作业正常写出 `preview.jpg`。失败随该作业的配置走，不随会话或 `model_id` 走。
3. **失败发生在栅格调用成功之后**：46 份 `native.log` 显示 `display`/`refit`/`refresh`/`repaint`/`raster` 全部返回 0，之后才落到 `output_file`；`window=1001`、`window_matches_model=true`、`current_window_matches=true`。
4. **本机至今没有空件失败的 `file_check` 现场**：这 46 个作业全部早于 T08A 诊断提交 `0b26c66`（2026-10-28 23:12），一个都不带 `file_check`。已有 240 个带 `file_check` 的作业全部是**有操作**的。
5. **外部现场与本机签名逐字一致**：R80x-3/R80x-6 记录空件 `file_check.exists=false`、`error_code=2`、`error_category=system`、`error_message="The system cannot find the file specified."`、`verification_error=FileNotFoundError`，并同样声明 `view_matrix_matches` 全程 false。本机 46 个作业的 `view_matrix_matches` 也全为 false，**该布尔值在失败与成功两侧同为 false，不能作为失真判据**（与 BUG-066/T08C 既有结论一致）。

**未定因**：Creo 为何在零操作的新模型上返回栅格成功却不落文件，离线无法判定，需实机在该配置上重跑以取得带 `file_check` 的现场。按“有真实可复现 I/O 原因才做最小修复”，**本阶段不修生产代码、不加自动重试或落盘确认轮询**；也不据此关闭本卡。

**0.8.3 实机“未复现”的原因已定位**：`tools/test_t07_preview.py` 原夹具全部是**带操作**的模型（盘体→切除→阵列→显式导出），结构上不可能触发空件场景——夹具里根本没有空件。本次已补该覆盖（见下）。

**驱动覆盖（本次修改，测试工具非生产代码）**：`tools/test_t07_preview.py` 新增 `empty_part`（用外部报告点名的 `creo_new_part`，**允许失败并记录**而非断言写出）、`empty_part_solid`（同一 `model_id` 续建实体）、`sheetmetal_wall`（XZ 面 185 mm 单线 + `sheetmetal_wall` 232×1 mm 钣金对照）；报告与图像目录改为按 run_id 唯一（`build/post090_n11_preview/<run_id>/`），**既有报告拒绝覆盖**（连接前退出码 2），不再覆盖历史 `build/t07_preview_acceptance.json` 与 `build/t07-preview/`。`tests/unit/test_t07_preview.py` 新增 9 项：空件失败被记录而不掩盖、**缺失图像不能通过**、实体写出保留图像并标记 `human_review_pending`、报告唯一性与拒绝覆盖。

**单测**：`-m unittest tests.unit.test_t07_preview -v` → exit 0，Ran 36 tests，OK（原 27 + 新 9）。ruff 检查与格式均通过。
