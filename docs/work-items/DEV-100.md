## 第一批进展

BUG-186 和 FEAT-084 已完成本机 Creo 10 的 Arm2 毛坯、厚度侧对照、旧调用与回滚验证。BUG-130 的独立作业预算、六个网格阶段与终态诊断已实现并用 Arm2 毛坯验证。原超时样件、Arm7 选边和其它反馈项仍按上表推进。

当前能力核对确认旋转已有真实外部轴引用，可传 `axis` 几何 ID 或 `datum_axis_feature` 标签。报告中的两点式坐标轴和弧度入口仍未支持。显式 `geometry_tolerance_mm` 已在两种求解模式使用同一硬上限，省略字段时的缺省值和超差处理随求解模式变化。

Windows x64 / Python 3.12.10 的 `python tools/dev_check.py --work-item DEV-100` 通过，全量 4497 项，零失败、零错误、7 跳过，三项离线门禁通过。受测基点 `1e2cea90d3337a6401760bf50b7b07a05944f7f5`，dirty=true，源码指纹 `4d143313ef2a134b418b4907b61fc94b93e3829431732a78245f73f60adf6dfe` 与最终 Creo 作业一致。钣金与 STL Python 专项 128 项通过，独立 STL C++ 回归 24 项通过。

源码核对补充。原生 `open_end_samples` 已存在，仍需验证其在失败回执的定位能力；`snap_endpoints` 缺省 false，现有 Python 重写限制两条圆弧的联合改写。`bounding_box_mm` 当前来自 `ProSolidOutlineGet`，Creo 10 SDK 将其定义为不含基准和注释的再生外包络。原件观察到的多出 0.1 mm 仍待原样件复测，当前证据不足以把它定性为控制点包络。服务自身版本可从 `creo_capabilities` 或 `creo_session_status.server_version` 查询，已连接的 Creo 发版编号来自本次作业的 `creo_release_numeric`。

## 草图闭合、公差说明与旋转输入进展（§4、§5、§8–§9）

- **§4 草图弧-线闭合焊合与开放端诊断**：`endpoint_welding` 的 `_plan()`/`weld_eligibility()`/`prepare_endpoint_weld()`/`prepare_operations()`/`annotate_result()` 接入显式 `closure_tolerance_mm`（省略保持默认 `1e-4 mm`），`snap_endpoints=true` 支持多缝开放链（`line-line`/`arc-line`）按最小间距安全焊合（仍拒绝桥接已闭合环、拒绝超 `max_endpoint_move_mm`、拒绝两圆弧静默空转），同计划 `validate_operations` 在 `snap_endpoints=true` 时按焊后预览轮廓预检；原生 `section_profile_summary` 对 `open_end_samples` 按 `nearest_gap_mm` 升序排列并补充 `nearest_point`，`extrude_or_revolve` 在创建失败（含 `ProFeatureWithoptionsCreate=-1` 与 `PRO_FEAT_FAILED`）时将 `native_section` 写入操作回执并在错误文案追加前 5 条 `Nearest open ends:`。
- **§8–§9 旋转两点式坐标轴与弧度/整圈收敛**：`RevolveAxis` 与原生 `extrude_or_revolve` 新增 `axis={"kind":"sketch_points","start_mm":[u1,v1],"end_mm":[u2,v2]}`（及简写 `{"start_mm":[...],"end_mm":[...]}`），原生在目标草图按存储的 `(u,v)` 坐标投影并添加或复用共线的 `PRO_2D_CENTER_LINE`（保留原封闭轮廓边界线，冲突既有用户中心线时拒绝回滚）；`RevolveOp` 与 `creo_revolve` 新增 `angle_rad` 弧度入口并对 `(360, 360.001]` 度（如 `6.28319 rad = 360.000269°`）受控收敛到 `360.0°` 并回执 `angle_clamped_from_deg`（超过 `360.001°` 或同时传 `angle`/`angle_rad` 均拒绝）。
