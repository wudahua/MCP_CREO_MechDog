# BUG-126：无图形会话中 `ProWindowActivate` 失败导致建模误判失败

## 当前摘要（2026-11-13）

分类：**已完成**。类型：缺陷。优先级：P1。目标版本：0.24.1。

来源：本机 2026-11-13 实机验证 [BUG-125](BUG-125.md) 时发现。关联报告 P-07（旧驱动 TDR 蓝屏的规避路线）。

## 问题或目标

Creo 12.4.0.0 以 `-g:no_graphics` 启动后 Toolkit 连接正常，但板件建模任务失败：

- 作业 `0d7d3a5c034c469f8bc28ed37e6488e2`：`status=failed`、`toolkit_code=-8`、`saved_file_reloaded_and_verified=false`。
- 日志显示几何全部完成：`ProSurfaceDataGet=0`、`ProSolidMassPropertyWithDensityGet=0`、`volume_mm3=12475.327397218973`（解析值 12475.3274122872）、`ProMdlDisplay=0`、`ProMdlWindowGet=0`、`ProWindowCurrentSet=0`、`ProViewMatrixSet=0`、`ProWindowRefit=0`、`ProWindowRepaint=0`。
- 唯一失败调用：`ProWindowActivate(win)=-8`（`PRO_TK_E_NOT_FOUND`）。

根因：`native/worker.cpp` 的 `create_plate()` 把「激活模型窗口」这个 UI 步骤当作成功条件；无图形会话没有可激活窗口，于是几何、存盘、重载校验都通过的任务被判失败。影响：报告环境想用无图形模式规避蓝屏时，验收必定失败，路线会被误判为不可行。

## 范围

包含：`ProWindowActivate` 只记录返回值并写 `window_activate_code`，不再抛错；同处其余窗口步骤保持严格（同一无图形会话实测返回 0，失败仍属真实异常）；成功判定仍要求几何断言与保存重载。

不包含：`generic.cpp`、`drawing.cpp` 等其它原生路径的同名窗口调用；无图形下的预览质量评估（`preview_code` 仍按实际返回记录）。

## 验收标准

| 环境 / 用例 | 命令或操作 | 可判断的预期结果 |
| --- | --- | --- |
| Windows / Python | `tools/dev_check.py` | 无新增语言问题，单元回归通过 |
| Creo 12.4 / `-g:no_graphics` | 提交板件建模 | `status=succeeded`、体积与解析值一致、重载通过、`window_activate_code=-8` |
| Creo 12.4 / GUI | 同一模型重建 | 行为不变，`window_activate_code=0` |

## 实现与证据

`native/worker.cpp`（全局 `window_activate_code`、`create_plate()` 末尾、结果 JSON）。实机双向结果见[本次证据](../validation/STARTUP-HEADLESS-2026-11-13.md#bug-126)。
