## 1. 核心问题 A（P1）：Creo 10 编译阻断跨 0.8.3 / 0.8.4 / 0.8.5 三版未修，且上轮报告未被接收

### 现状（0.8.5 复核）

| `tools/generate_constants.py` 的 `PROBES` | 仍只有 2 个常量（`PRO_E_HLE_ADD_PARAMETERS`、`PRO_HOLE_NO_PARAMETERS_FLAG`），未增加函数探测 |
| 发布说明表述 | 0.8.3「Creo 10 独立复测均尚未验证」；0.8.4/0.8.5「Creo 10 未独立复测」——读起来像"没测"，实际是**编译不通过** |

时间线说明（不苛责 0.8.3）：我的报告 10-29 15:36 产出，0.8.3 于同日 15:33 发布，差 3 分钟，来不及吸收属正常；但 **0.8.4（21:38）与 0.8.5（23:43）各有 6–8 小时窗口**，仍无变化，且报告未进入归档队列。

### 为什么这条值得优先处理

1. **代价是整个 SDK 世代**：Creo 10 用户 `bridge.py build` 直接失败，装不上，后面所有能力都无从谈起。README 第 5 行仍写"连接 Creo Parametric 9 / 10 / 12"，第 43 行安装示例仍是 `-CreoRoot 'C:\Program Files\PTC\Creo 10.0.0.0'`。
2. **本轮的旁证让守卫几乎零代价**：作者自己 10-29 在 [BUG-032](../work-items/BUG-032.md) 第六轮发现，这个 API 在 **1 mm 薄板上读出 3.71 mm**（零件级默认板厚未随壁厚同步），并写明"`part_thickness_mm` 及任何'宽 ≥ 板厚'规则在修正前不可信"。也就是说：**这两个字段目前本就不可信**，在 Creo 10 上退化为 `null` 不损失任何可用信息。
3. **仓库已有现成机制**：BUG-033 的编译探测（`constants.inc` + `MECHDOG_HAS_<名>`）就是为旧 SDK 缺失符号设计的，只需从"常量"扩展到"函数声明"。

### 可以直接采用的最小修复

```python
# tools/generate_constants.py —— 增加函数声明探测（与现有 PROBES 并列）
FUNCTION_PROBES = ("ProSmtPartThicknessValueGet",)
# 命中则在 constants.inc 追加： #define MECHDOG_HAS_ProSmtPartThicknessValueGet 1
```

```cpp
// native/advanced.cpp —— 与代码既有的"厚度未知→null"降级对齐
    double thickness = 0;
#ifdef MECHDOG_HAS_ProSmtPartThicknessValueGet
    bool thickness_known =
        ProSmtPartThicknessValueGet(ProMdlToPart(board), &thickness) == PRO_TK_NO_ERROR;
#else
    bool thickness_known = false;
#endif
```

Creo 12.4 下宏命中、行为与现在逐字节一致；Creo 10 下 `part_thickness_mm` / `width_at_least_thickness` 为 `null`。附带建议：发布说明把"Creo 10 未独立复测"改为可判定的"**Creo 10：当前不可编译（缺 X API）**"或给出"SDK 门控 API 清单"，避免下一位 Creo 10 用户在安装阶段撞同一堵墙。

另外"**重启后几分钟内自行退出，只留 pro_comm_msg**"是**新现象**（前两次是连不上，这次是起不来/起来了又倒），目前只写在版本说明里，没有进任何条目的现象清单。
