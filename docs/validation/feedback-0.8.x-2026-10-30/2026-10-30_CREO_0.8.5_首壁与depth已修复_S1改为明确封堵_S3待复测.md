## 二、已修复项验证

### ✅ R1 首个壁（上一轮的阻断级回归）
- 用例：XY 平面（offset 0）+ 1 条线 (-92.5,0)→(92.5,0) + `sheetmetal_wall`。
- 结果：**成功**，`features: 9 / surfaces: 6 / edges: 12`，`native_section.reference_entities: 2` 不再被误计。
- 上一轮同一草图报 `the section has 2 drawing entities (1 straight lines)` —— 计数口径已修正。

### ✅ S5 `depth` 语义（连续 6 轮的老问题，本轮终于修好）
- 用例：`sheetmetal_wall(depth=1.0, thickness=232.0)`，草图线长 185。
- 结果：体积 **42 920 = 185×232×1**，`center_of_gravity: [0,0,0.5]` —— 完全正确。
- 对比：0.3.1 → 0.7.2 一直返回 9 957 440（185×232×**232**，质心 z=116）。
- **意义**：终于可以直接用 `sheetmetal_wall` 铺 1 mm 底板，不必再绕道 YZ 平面 + offset。

### ✅ S1 已升级为"明确封堵"（从失败变可用性改善）
现在提交钣金件上的 `extrude(mode="add")` 会在**执行前**被拦截，返回可识别错误码：
```
SHEETMETAL_SOLID_ADD_UNSUPPORTED: Creo rejects an extrude add that merges solid material
into a sheetmetal body (ProFeatureWithoptionsCreate returns -1, measured on Creo 12.4.0.0
with and without overlap). Add material with sheetmetal_wall or sheetmetal_flange, or request
new_body=true to create a separate solid body; cut, surface and thin extrudes are unaffected.
Blocked operations: ex_tb
```
这条信息质量很高：给出**结论**（Creo 自身拒绝，且已在 Creo 12.4 上“有/无重叠”各测一次）、**替代路径**（sheetmetal_wall / sheetmetal_flange / `new_body=true`）、**影响范围**（cut / surface / thin extrude 不受影响）。
→ 作为使用者我接受这个"标注为不支持 + 给出替代"的处理方式（前几轮我提的诉求正是"修复或给出可识别错误码"）。

> **后续可探索**：`new_body=true` 提示可以把凸台/铰链销做成**独立实体 body**。若能确认可行，第二轮配电箱的冲压凸台与铰链座销就有落地路径了 —— 建议在文档中给一个"钣金件上挂独立实体的最小示例"。

## 四、仍存在问题

### N3 `preview` 写文件失败（第 3 轮出现）
- 新建空零件仍返回 `preview_status: failed / failed_step: output_file / failed_code: -4`。
- **但新增了 `file_check` 诊断**（本轮新增）：
  ```json
  "file_check": {"stage":"after_raster","parent_exists":true,"exists":false,
                 "error_code":2,"error_category":"system",
                 "error_message":"The system cannot find the file specified."},
  "verification_error": "FileNotFoundError"
  ```
  → 明确显示：父目录存在、栅格化各步返回码全 0、但**文件根本没被创建**。这把排查范围缩到了"Creo 的 raster 输出没有真正落盘"。
- 建议：`raster` 调用后加一次短轮询（如 100–300 ms 内检查文件出现），或改用 `ProPixelmapSave` 之类同步落盘接口；否则同一 job 内下一次调用就会正常（本轮第 2 次调用即 `preview_status: written, bytes: 11230`）。
