# CREO 10.0.0.0 × MCP_CREO_MechDog 0.8.2 反馈：0.8.x 在 Creo 10 SDK 上无法编译（ProSmtPartThicknessValueGet 缺失）

- 日期：2026-10-29（Asia/Shanghai）
- 反馈环境：Windows x64 / Creo Parametric **10.0.0.0**（Toolkit SDK 同版本）/ VS2022 BuildTools 14.44.35207 / Python 3.13 / `vcvars64_env` 三键
- 升级路径：0.7.2 → **0.8.2**（跨 0.8.0 / 0.8.1）
- 验证边界：遵守"停止新的 Toolkit 连接"约束，本轮仅安装/编译/文件/静态验证；所有需实机项记"未验证"

## 1. 核心问题（P1）：0.8.0 起源生代码在 Creo 10 SDK 上必然编译失败

### 现象

`bridge.py build` 失败（0.7.2 同环境一直一次通过）：

```
native/advanced.cpp(487): error C3861: "ProSmtPartThicknessValueGet": 找不到标识符
native/advanced.cpp(487): error C2677: "==" : 没有找到接受"ProErrors"类型的全局运算符(级联错误)
```

### 取证

1. **Creo 10 SDK 全目录检索无此声明**（`Common Files/protoolkit/includes` 全部 `.h` 中 grep 无结果）；Creo 10 也无 `ProSmtPart.h`，无可用的版本条件宏（`PRO_TK_VERSION` 等均不存在）。
2. **系统性扫描**：对 0.8.2 相对 0.7.2 的全部 5 个原生改动文件（`advanced.cpp` / `generic.cpp` / `preview.h` / `sketch_coordinates.cpp` / `sketch_edit.cpp`）提取所有 `Pro*` 调用并与 SDK 声明文本比对，**缺失的只有这一个 API**（advanced.cpp 一次调用）。
3. 用法位置：`flange_relief_record()`（DEV-051 T05 法兰壁 relief 校验），`part_thickness_mm` / `width_at_least_thickness` 两个**信息性字段**。关键是：**代码本身已实现"厚度未知 → null"的降级路径**（`thickness_known ? J(thickness) : J()`）。
4. 文档现状：README 第 5 行仍写"连接 Creo Parametric 9 / 10 / 12"，第 43 行安装示例仍是 `-CreoRoot 'C:\Program Files\PTC\Creo 10.0.0.0'`；COMPATIBILITY.md 将 Creo 10 定位为"历史实测环境；功能按已有范围声明"。发布说明写"**Creo 9/10 未验**"——但实际比"未验"更严重：**不是没测过，是编译不通过**。作者验收摘要的"`bridge.py build` 成功"仅对 Creo 12.4 SDK 成立；1341 项离线测试不含"针对旧 SDK 编译"这一维度。

### 建议（成本低，且有本仓库自己的先例可复用）

项目已有处理旧 SDK 的机制：**BUG-033 编译探测**（`tools/generate_constants.py` 每次构建幂等生成 `constants.inc`，对缺失常量生成 `#define MECHDOG_HAS_<名> 1` 探针宏）。建议把该机制**从"常量探测"延伸到"函数声明探测"**：

1. `generate_constants.py` 增加函数探针：在 SDK 头中 grep `ProSmtPartThicknessValueGet`，命中则生成 `#define MECHDOG_HAS_ProSmtPartThicknessValueGet 1`（命名沿用现有 `MECHDOG_HAS_` 家族）。
2. `advanced.cpp` 该调用包一层 `#ifdef MECHDOG_HAS_ProSmtPartThicknessValueGet`，`#else` 分支 `thickness_known = false`。
3. **运行语义零回归**：Creo 12.4 下宏命中、行为与现在逐字节一致；Creo 10 下 `part_thickness_mm` / `width_at_least_thickness` 变 null——这正是代码已支持的降级路径，且这两个字段只是 T05 校验的信息性输出。
4. 顺带：发布说明/COMPATIBILITY.md 增加一列"SDK 门控 API 清单"（或把"Creo 9/10 未验"细化为"Creo 10 当前**无法编译**"），避免下一个 Creo 10 用户在安装阶段撞同一堵墙。

## 2. 本机处置（透明披露）

为完成升级，我对本机 `native/advanced.cpp` 打了最小补丁（+7 行）：

```cpp
#ifdef MECHDOG_HAS_ProSmtPartThicknessValueGet
    bool thickness_known =
        ProSmtPartThicknessValueGet(ProMdlToPart(board), &thickness) == PRO_TK_NO_ERROR;
#else
    // Local (Creo 10 SDK): ProSmtPartThicknessValueGet is not declared in this SDK.
    bool thickness_known = false;   // 走代码既有的 null 降级
#endif
```

- 宏名与现有 `MECHDOG_HAS_` 家族对齐：**若作者按 §1 建议上游化，本补丁可直接删除、零冲突**。
- 补丁后编译通过：worker 9,409,536 → 9,478,144 B（worker 指纹 `c703dee5…`，含本地补丁；与上游 0.8.2 的官方 worker 指纹不同属预期）。
- ⚠️ 后续升级如上游未落官方守卫，此补丁需重新套用。
