## 2. 【唯一遗留·连续 3 轮未修】多轮廓截面仍只支持 2 个

本轮用同一份未被消耗的 5 环草图 `probe_gear5_sk`（5 个独立 4 弧链闭环，位于 XY offset 2.5）再次提交：

```
status: failed
stage: executing_feature_plan
message: Extrude feature creation failed (ProFeatureWithoptionsCreate=-1).
  Toolkit rejected the referenced sketch section; the return code alone does not
  identify whether closure, a geometric condition or the feature tree caused it.
  Detected native section: 5 closed contour(s), 5 contour(s), 20 entity(ies), 0 open end(s).
  These counts do not identify the cause; the cause is not determined. Sketch: 'probe_gear5_sk'.
```

与 v0.7.0、v0.7.2 的报错**逐字相同**。

### 2.1 已知边界（历轮累积）

| 轮廓 | 实体 | 结果 | 验证版本 |
|---|---|---|---|
| 1 条 4 段弧闭环 | 4 | ✅ | 0.5.2 – 0.8.2 |
| **2 个独立圆** | 2 | ✅ `material_removed_mm3 = 125.663706`（= 2·π·4·5，精确） | 0.5.2 / 0.6.1 |
| 5 个独立 4 弧链闭环 | 20 | ❌ | 0.5.2 / 0.6.0 / 0.6.1 / 0.7.2 / **0.8.2** |
| 10 个独立 4 弧链闭环 | 40 | ❌ | 0.5.2 / 0.6.0 |

### 2.2 建议（第三次提，这次给出更具体的定位方向）

报错已明确"5 closed contour / 0 open end"，说明 section 本身没问题。剩下只可能在两处：

1. **contour 标记**：Creo 的 extrude section 需要把每个 contour 标成外环/内环（`PRO_E_STD_SECTION` 的数量与 `PRO_SECTION_CONTOUR` 的归属）。2 个圆能过、5 个弧链不能过，怀疑是"每 loop 的 entity 归属"或"loop 数量上限被写死"。
2. **弧链 loop 的闭合判定**：圆是单实体闭环，弧链是多实体链式闭环。若代码用"单实体即闭环"的简化判定，就会出现"圆过、链不过"。

**加一条回归用例即可锁死**：`2 个圆 + 5 个 4 弧链闭环` 必须在同一版本内同时通过。素材 `scripts/gear10.json`（10 环 40 弧，取前 20 条即 5 环）。

**报错建议补一句**：`detected 5 contours, supported 2`（目前只说 counts 不解释，用户只能靠试）。

### 2.3 影响

规格要求的"齿轮 10 槽一次切净"仍需用 `axis_pattern` 绕行（Part4 即绕行结果，精度 −0.0066%，正确性无碍）。属效率与特征树形态问题，不是正确性问题。

## 5. v0.8.x 的新增可观测性（正面）

本轮装配过程中观察到多处诊断增强，都很有用：

| 新增 | 价值 |
|---|---|
| `component_changes`：每次装配返回 `{op: added, label, feature_id, source_model_id, source_revision}` | 可直接核对"装进去的是哪个版本"——本轮就靠它确认 5 根摆杆都是 rev 15 |
| 组件段新增 `label` / `labels` / `label_state` / `source_model_id` / `source_revision` / `bindings` / `identity` | 组件与源零件的可追溯性完整闭环 |
| `constraints[].type_name`（如 `"fix"`） | 不再只有数字枚举 |
| `inspection_summary.body_counts`（objects / records / active / with_material / without_material，并附 `counts_meaning` 说明） | 多实体场景可直接看有几体、几个有料 |
| `preview.file_check`（absolute / parent_exists / exists / is_file / size / error_code / error_message） | 预览失败能定位到"文件没写出来"而不是模糊的渲染失败 |
| `session_health.next_steps` 细分 `keep-evidence` / `verify-next-save` / `recover` / `escalate`，并点名 **BUG-078** | 会话健康从"状态"升级为"处置建议" |

### 仍存在

| 问题 | 说明 |
|---|---|
| **`preview` 目视仍不可靠** | 本轮所有 job 的 `view_matrix_matches` 都是 `false`；空模型时 `preview.status: failed / failed_step: output_file / failed_code: -4`。虽然现在失败原因写得很清楚，但**正常 job 的图仍不能用于目视验收**（Part1 的预览只画出中心几条放射条带，而体积是完整的 14109.45） |
| **无删除特征** | 仍无 `creo_delete_features`。多轮试错已积累：`probe_npp_v061`、`part4_pinion_v2`、`part1_star_frame`（旧）、`assem1_iris`（旧）等一整套可清理对象，目前只能留着 |
| **无批处理** | 1 特征 = 1 job。本轮 9 次装配 job 耗时 10–15 s/次；Part1 因 1408 条边，建模 job 曾达 50–60 s |
| **`creo_extrude` 无 `draft_angle` / `direction_vector`** | 方向已修；拔模仍要另调 `creo_draft`；`direction_vector` 仍建议加作自证兜底 |
| **label 规则未文档化** | `^[a-z][a-z0-9_]{0,27}$`，报错不提示"改小写" |
