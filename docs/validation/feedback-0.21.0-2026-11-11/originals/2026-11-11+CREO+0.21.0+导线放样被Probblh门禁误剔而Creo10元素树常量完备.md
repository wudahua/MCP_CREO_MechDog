# 2026-11-11 CREO 0.21.0 导线放样被 `Probbl.h` 门禁误剔，而 Creo 10 元素树常量完备可编译

> 反馈对象：MCP_CREO_MechDog 作者
> 实测环境：Windows / **Creo Parametric 10.0.0.0**（`release_numeric=42`）/ MCP_CREO_MechDog **0.21.0**
> / Toolkit SDK `D:\Program Files\PTC\Creo 10.0.0.0\Common Files\protoolkit\includes`（415 个 `.h`）
> / MSVC 17.14.40（14.44.35207）
> 任务约束：用户要求「球鼻艏按 MCP 曲面能力继续推进，**不要近似方法**；发现问题写清楚」。

---

## 一、结论先行

**0.21.0 把球鼻艏最需要的能力做出来了，但在 Creo 10 上一次都调用不了。**

- 肯定：`surface_loft` 新增 `guides`（2–8 条第二方向导线）、`sections` 放宽到 2–32、`smooth` 插值，
  正是 2026-11-10 反馈清单第 1 条「多截面 + 纵向导线 boundary blend」的直接落地，响应非常快。
- 问题：Creo 10 的 worker 把整个 `surface_loft` 实现**编译剔除**，真机提交即
  `SURFACE_LOFT_SDK_UNAVAILABLE`，无 job、无几何。
- **本次最重要的发现**：这不是 Creo 10 的能力限制，而是**门禁条件设错了**。
  `native/surface_loft.cpp` 只依赖 5 个 `PRO_E_BNBLN_*` 元素 ID，这 5 个在 Creo 10 的
  **`ProElemId.h` 里全部存在**；`ProFeatureWithoptionsCreate` 也在 `ProFeature.h`。
  本机用 Creo 10 SDK 头文件写的最小 C++ 探针 **0 error 编译通过**（不含 `Probbl.h`）。
  换言之：**把门禁从「有没有 `Probbl.h`」改成「有没有 `PRO_E_BNBLN_CURVES`」，
  Creo 10 就能直接获得 0.21.0 的导线放样能力。**

按用户「不做近似」的要求，本轮**没有**回退到 TXT 行 92 的分段椭圆柱降级路径，
主模型未做任何改动。

## 五、根因定位：门禁误设（本节为可修复性的核心证据）

### 5.1 `native/surface_loft.cpp` 实际依赖什么

文件头注释写「The tree comes from Probbl.h, the only documented boundary-blend tree on this SDK」，
并用 `MECHDOG_HAS_PROBBL_HEADER`（`__has_include(<Probbl.h>)`）把**整个实现**包进 `#if`；
缺头时只剩 `mechdog_surface_loft_sdk_state()` 和抛 `SURFACE_LOFT_SDK_UNAVAILABLE` 的 stub。

但该文件全文引用的 boundary blend 符号只有 5 个：

```text
PRO_E_BNBLN_CURVES      PRO_E_BNBLN_1DIR     PRO_E_BNBLN_2DIR
PRO_E_BNBLN_DIR_CURVES  PRO_E_BNBLN_TAN_COND
```

外加 release notes 提到的 `PRO_E_STD_CHAIN_HOLDER`，以及通用元素树 API
（`ProElement.h` / `ProFeature.h` 的 `ProFeatureWithoptionsCreate`）。
**没有引用 `Probbl.h` 独有的类型或函数。**

### 5.2 Creo 10 SDK 实测（`ProElemId.h`）

| 常量 | 行号 | 值 |
|---|---:|---:|
| `PRO_E_FEATURE_TREE` | 436 | 386 |
| `PRO_E_BNBLN_TAN_COND` | 516 | 459 |
| `PRO_E_BNBLN_ADV_VIA_CRV` | 528 | 471 |
| `PRO_E_BNBLN_1DIR` | 743 | 651 |
| `PRO_E_BNBLN_2DIR` | 744 | 652 |
| `PRO_E_BNBLN_DIR_CURVES` | 749 | 657 |
| `PRO_E_BNBLN_CURVES` | 753 | 661 |
| `PRO_E_STD_CHAIN_HOLDER` | 2302 | 3058 |

`ProFeature.h:462` 有 `ProError ProFeatureWithoptionsCreate(...)`；
`ProElement.h` 有 `ProElementAlloc` 等元素树函数。
`Probbl.h` 在整个 Creo 10 安装目录下确实为 0 个文件，但**这不构成功能缺失**。

### 5.3 最小编译探针（`cl /c`，Creo 10 SDK，不含 `Probbl.h`）

- 源文件 `_creo10_bnbln_compile_probe.cpp`：include `ProToolkit.h` / `ProElemId.h` /
  `ProElement.h` / `ProFeature.h`，引用上表 5 个常量、
  `ProElementAlloc(PRO_E_FEATURE_TREE, ...)` 与 `ProFeatureWithoptionsCreate` 地址。
- 运行脚本 `_compile_probe.py`（显式传入 MSVC / Windows Kits / Creo 10 SDK 头文件路径，
  不调用 `vcvars64.bat`，因为该脚本需要 `reg.exe`，本机沙箱阻止注册表查询）。
- 结果：`CL_RETURNCODE: 0`，`STDERR` 空，`_creo10_bnbln_compile_probe.obj` 生成 **1478 字节**，
  **0 error / 0 warning**。

> 证据边界：这是**编译级**证据，证明「用 Creo 10 SDK 可以编译出 boundary blend 元素树代码」。
> 它不等于「Creo 10 内核运行该元素树一定能再生成功」——运行期行为仍需作者修复门禁后真机验证。
> 本文不宣称运行期等价。

## 六、即使门禁修好，球鼻艏 TXT 原方案仍缺三项

按用户「不近似」的要求，如实列出，避免修完 P1 后仍交付不出精确球鼻艏：

1. **任意正交平面截面**：球鼻艏截面在 **YZ 平面按 X 递增**（船纵向），而 0.21.0 release notes
   把「任意正交平面截面」列入未测范围。上一轮已实测 `creo_create_sketch(plane="YZ", offset=X)`
   可建且偏差 0.0 mm，因此缺口只在放样工具对截面框架的假设。
2. **端点收敛到独立点**：TXT Sketch69 是 `A21 独立点 (78.094736179, 0, -5.6)`，
   作为放样收敛尖点；`sections` 只接受「每个草图恰好一条非复合曲线」，独立点无法参与，
   而 release notes 明写「端点收敛…未测」。
3. **样条 NURBS 参数入口**：`sketch spline` 仍只有 `points`（≤200），无 `knots`/`weights`/`degree`
   （上一轮 0.20.0 反馈第 2 条，0.21.0 未变）。TXT 附录 A18–A23 给的是带内部节点的精确
   NURBS，当前只能给点列拟合，不能宣称精确复现。

## 八、给作者的需求清单（按优先级）

1. **【P1，一次改动即可解锁 Creo 10 的 0.21.0 核心能力】重设 `surface_loft` 编译门禁**
   - 把 `native/surface_loft.cpp` 的 `#include <Probbl.h>` 换成/补上 `#include <ProElemId.h>`；
   - 门禁条件由 `MECHDOG_HAS_PROBBL_HEADER`（`__has_include(<Probbl.h>)`）改为
     「必需元素 ID 是否可用」，例如 `#if defined(PRO_E_BNBLN_CURVES) && defined(PRO_E_BNBLN_2DIR)`；
   - `mechdog_surface_loft_sdk_state()` 的判定同源；`generate_constants.py` 的
     `MISSING_SDK_HEADER=Probbl.h` 可保留为信息日志，但不应再决定功能可用性；
   - 修复后请在真实 Creo 10 上跑一次 `test_surface_loft_guides.py --live`，
     并用 `worker_build_identity.features.surface_loft.available` 回报结果。
   - 本机已提供可直接复跑的编译探针（`_creo10_bnbln_compile_probe.cpp` / `_compile_probe.py`）。
2. **允许 `surface_loft` 接受任意正交平面截面**（YZ@X、XZ@Y），沿平面法向放样。
3. **支持独立点/退化截面作为放样收敛终点**（对应 TXT Sketch69）。
4. **`sketch spline` 暴露 `knots` / `weights` / `degree`**（或明确区分控制点与插值点模式），
   使 TXT 原始 NURBS 可 1:1 复现；当前 `geometry_deviation.measurement=control_points`
   但 schema 未说明 `points` 语义。
5. `dimensioning="coordinates"` 支持 spline（当前明确拒绝，只能 `autodim`，实测引入 0.004 mm 刚性平移）。
6. `capabilities` 顶层增加「Creo 版本 → `surface_loft`（含 guides）可用性」速查字段，
   并把不可用原因与能力描述放在同一条目。
7. 发布非平面边界曲面工具，或明确给出无需 `Probbl.h` 的替代放样路径。
8. 提供 callback 的程序化注册/启动路径，或让实体 Blend 走无 callback 的元素树路线。
