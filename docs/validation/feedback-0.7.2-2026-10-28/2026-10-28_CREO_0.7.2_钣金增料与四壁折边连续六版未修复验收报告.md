## 二、复现细节

### S5 `depth=1` ❌
- `sheetmetal_wall(depth=1.0, thickness=232.0)`，草图线长 185 → 体积 **9 957 440 = 185×232×232**（应为 42 920），`center_of_gravity` z=116（板厚 232 的一半）直接佐证。
- `depth` 仍被 `thickness` 静默替换 → 无法直接用 `sheetmetal_wall` 铺 1 mm 底板，必须绕道（YZ 平面 + offset、thickness=1、depth=面内长边、direction=negative）。

### S1 钣金件增料 ❌
- 185×232×232 钣金壁 + 草图矩形 X 88..98 / Z 100..110（XZ 面）+ `extrude(add, depth=10, direction=negative)`。
- 该块与实体**真实体积重叠**（X 88..92.5 段），已排除"无重叠/仅共面"误判。
- 结果：`ProFeatureWithoptionsCreate=-1`；报错与 0.7.0 完全一致：
  > "Toolkit rejected the referenced sketch section… Detected native section: 1 closed contour(s), 1 contour(s), 4 entity(ies), 0 open end(s)… **the cause is not determined**."
- **强烈建议**：该截面 `profile` 报告 `closed_contour_count: 1 / material_area_mm2: 100` 完全正常，同一截面在普通零件上增料成功 → 请对比"钣金件 vs 普通件"两条 protrusion 实现路径（父特征/默认 body 选择、`ProFeatureWithoptionsCreate` 的 options 差异）。

### S3 封闭四壁盒 ❌
- 185×232×1 底板 → 一次挂 4 道折边（h=80, R2.54, Y=0.5，边 104/105/106/107）。
- 结果：`f_px`、`f_nx` 成功；**`f_ny` 失败**（index 4）；`f_py` = `not_executed`。与 0.3.1 → 0.7.0 行为完全一致。
- 仍无折弯释放（bend relief）参数 → 垂直折边在角部必然冲突。

## 三、保持已修 / 保持良好（值得肯定）

1. **S10 逐项结果**：失败时 `operations` 完整返回 `execution_status`（succeeded / failed / not_executed）+ `effect_status`（committed / rolled_back / no_effect），可精确知道哪几项已成功、失败在哪项。
2. **诊断诚实且信息量足**：不再虚构归因，明确 `the cause is not determined`，并给出 `native_section` 与 `profile`（八类异常计数、`material_area_mm2`、轮廓闭合数）。
3. **可追溯产物**：`inspection_ref` / `aliases_ref` 带路径 + sha256 + 字节数；`session_fingerprint`、`creo_release_numeric`(42)。
4. **`session_health`**：会话指纹、通道占用者、最近连接/保存、`damage_signals`、`next_steps`，并注明 `guarantee: evidence_only`；本轮 `historic_damage_signals` 已清空（上次的 `unknown_outcome` 记录已消解）。

## 四、本轮新发现 / 仍存在问题

### N3 `preview` 写文件失败（第 2 轮出现）
- 新建空零件 `623881590f3147639920de5d5ae1a0b2` 即返回：
  `preview_status: "failed"`, `failed_step: "output_file"`, `failed_code: -4`, `bytes: -1`；
  而 `preview.codes` 中 display→raster **全部为 0**（渲染链路正常，仅落盘失败），且 `view_matrix_matches: false`。
- 同一个会话内后续调用（`5038a5f5…`）又能写成功 → 属间歇性失败。
- 建议：失败时报告目标路径的存在性/权限/占用情况（很可能是上一次 job 的文件句柄未释放），或失败后自动重试一次。

### N1 钣金件 `bodies` 恒报 2 —— 仍存在
单个 6 面 / 12 边实体也报 `bodies: 2`，而实体件正确报 1 → 该字段对钣金件不可用。

## 五、建议（按收益排序，与上轮一致）

1. **修 S1（钣金件增料）** —— 六轮未修，钣金链路唯一硬阻塞。可用"同一截面在普通件成功 / 在钣金件失败"作为最小对照定位。
2. **修 S3 + 提供折弯释放**（`relief`：矩形/扯裂/圆形，或自动角部处理）。
3. **修 S5**：`depth` 不应被 `thickness` 覆盖；并在工具描述中画清 `线长 / thickness（面内、以线为中心）/ depth（垂直草图平面）` 三个方向。
4. **修 N3**：`preview` 的 `output_file` 失败（补占用/权限信息或自动重试）。
5. **N1**：修正钣金件 `bodies` 计数或注明不可靠。
6. **P11**：`creo_export_model` 增加 `native_bundle`（.asm + `C_*.prt` 一起导出）。
7. **S2 / S6 / P3 / P5**：前几轮已详述，仍未修，建议一并排期。
8. **changelog**：0.7.0 → 0.7.2 无变更记录，建议在 `creo_capabilities` 中提供，便于回归定位。
