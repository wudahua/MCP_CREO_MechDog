## 2. 【已修复】v0.7.0 的新阻塞：倾斜面草图

### 2.1 按上轮建议的验证顺序，两步都通过

上轮我给的验证方案是"在新零件上先建 4 线矩形，再建 30 段截面"。本轮在 **同一个** `part1_star_v2`、**同一个** 倾斜面（id 163，法向 (0.587785, 0.809017, 0)）上执行：

| 步骤 | 上轮 v0.7.0 | **本轮 v0.7.2** |
|---|---|---|
| 4 线矩形（u∈[−4,0]） | ❌ 失败 | ✅ 成功（`material_area_mm2 = 24.0`） |
| 30 段斜槽闭环 | ❌ 失败 | ✅ **成功**（`material_area_mm2 = 15.57317477042468`，30 实体 / 1 闭环 / 0 开放端） |

同一个模型、同一个平面、同一份截面——上轮 4 次全败，本轮前两次就连过。**"一次 autodim 失败污染后续草图"这个推断不再成立，问题应已从根上修掉。**

### 2.2 连带结果：P02 首次建成

修好这一步之后，Part1 的 5 条贯穿斜槽第一次做出来：

| 步骤 | 参数 | 结果 |
|---|---|---|
| 星形花盘 | 20 段闭环 → 拉伸 5 | 16106.266433（`material_area_mm2 = 3221.253287`，与解析面积一致） |
| 种子斜槽 | `cut` + `symmetric` + `through_all`（沿面法向） | **−675.970240** → 15430.296193 |
| 5×72° 阵列 | 绕 Z 轴（`axz`） | **−1751.959973**（4 个实例，含重叠抵消）→ 13678.340213 |
| 中心凸台 Ø7.95×7 | 拉伸 −7 | **+347.491586** → 14025.831807 |
| 侧凸销 Ø3.9×7 | 拉伸 −7 | **+83.621342** → **14109.453149** |

**Part1 目标 12852.8，实测 14109.4531，偏差 +9.78%**（上轮同一零件只有花盘 16106.27，缺全部斜槽）。

### 2.3 剩余 +9.78% 的来源（诚实说明）

- 未做 **R3 圆角（9 条竖棱）与 2 处倒角**：这部分应再减约 150–200 mm³，未实施（`creo_round` 需选边，本轮未展开）。
- 斜槽总切除 2427.93 mm³，而按目标反推应约 3500 mm³（缺口 ≈1070）。
  几何上，5 条槽各自是距轴线 **8.66 mm**、4 mm 宽的弦向通道，法向间隔 72°，两两相交于半径 8.66/cos36° ≈ **10.7 mm** 处——重叠区大幅抵消，单槽独立切除 675.97 但 5 槽合计只有 2427.93（无重叠应为 3380）。**源模型的斜槽总切除量比"5 份不重叠的我的种子"还大**，说明单槽本身应更"肥"（更深或更宽）。这一点未能定位，属**几何取值的残差，不是功能缺陷**。

## 4. 【唯一遗留】多轮廓截面仍只支持 2 个

v0.7.2 实测（`part4_pinion_v2`，`probe_gear5_sk`，5 个 4 弧链闭环）：

```
Extrude feature creation failed (ProFeatureWithoptionsCreate=-1).
Toolkit rejected the referenced sketch section; the return code alone does not identify
whether closure, a geometric condition or the feature tree caused it.
Detected native section: 5 closed contour(s), 5 contour(s), 20 entity(ies), 0 open end(s).
These counts do not identify the cause; the cause is not determined. Sketch: 'probe_gear5_sk'.
```

对照（同一版本、同一零件、同一 `cut/through_all`）：

| 轮廓 | 实体 | 结果 |
|---|---|---|
| 2 个独立圆 | 2 | ✅ `material_removed_mm3 = 125.663706`（= 2·π·4·5，精确） |
| 5 个 4 弧链闭环 | 20 | ❌ 上述报错 |

报错已经把最要紧的事实说清楚了：**5 个闭合轮廓、0 个开放端** —— 截面合法，问题在 `ProFeatureWithoptionsCreate` 的 section 传参路径。

### 4.1 建议

1. 在 section 构建处打印每个 contour 的 loop ID / 材质侧 / 是否被标记为外环，2 contour 与 5 contour 走同一段代码时应能立刻看出差异。
2. 加回归用例：**2 个圆 + 5 个 4 弧链闭环必须在同一版本内同时通过**。用例素材 `scripts/gear10.json`（10 环 40 弧，取前 20 条即 5 环）。
3. 报错里补一句"detected N contours, supported M"（目前只说 counts 不解释原因，还需人工猜上限是 2）。

### 4.2 影响

规格要求"齿轮 10 槽一次切净"，本轮仍只能用 `axis_pattern` 绕行（Part4 已是绕行结果，精度 −0.0066%，可接受）。这项不影响正确性，只影响效率与特征树形态。
