## 1. ❌ P1（核心问题，第五次报告）：草图弧无 dir 参数且恒 CCW

### 1.1 静态证据（0.7.2 源码，与 0.7.0 逐字相同）

- `src/creo_mechdog/schema.py:139-148`：`Arc` 仅 `start_angle`/`end_angle`，无方向字段；
- `native/generic.cpp:1375` 与 `:2177`：`if (a.end_angle <= a.start_angle) a.end_angle += turn;` 恒 CCW，无 >180° 告警；
- `src/creo_mechdog/profile_diagnostics.py:95`：`sweep = (end - start) % _TWO_PI` —— 分析器同样以 CW 书写为 270° 主弧计面积，与原生同源。

### 1.2 实机对照实验（与前三轮完全一致）

| 模型 | 弧书写 | 体积 (mm³) | `profile.material_area_mm2` | 判定 |
| --- | --- | --- | --- | --- |
| `rt072_arc_ccw`（`0cb80fbb…`，job `e127b4be…`） | 0°→90° | **142.69908169840258** | 28.53981633974483 | 与解析劣弓形一致 ✓ |
| `rt072_arc_cw`（`c4785bb4…`，job `77c7ea74…`） | 90°→0° | **1428.0972451017306** | 285.6194490192345 | 主弧（270° 扫过），零告警 |

四个版本（0.3.3/0.3.5/0.7.0/0.7.2）实测值**逐位相同**，缺陷自 2026-10-14 首报以来从未变化。

### 1.3 持续的风险陈述

- 这是全工具链唯一**静默产出错误几何**的路径：体积非零、形状错误、`profile` 校验全绿（分析器与原生同源互证）；
- 0.7.0 新增的切除守卫按"去料量=0"判定，拦不住它；
- T06 结构化诊断对它免疫；
- 对逆向重建类任务（逐特征体积/面积比对验收），它能穿透全部数值验收。

### 1.4 建议（第四次提出，附带最低成本方案）

按优先级：
1. **告警方案（成本最低）**：`profile_diagnostics.py:95` 处 `sweep` 已算出，`sweep > π` 时在 `profile` 块加一条 `sweep_warnings`（实体名+扫过角度数）。这同时能暴露"分析器面积跟着 CW 书写走"这一事实，让调用方至少知道存在歧义。
2. **`dir` 字段方案**：`Arc` 增加 `dir: +1 | -1`（默认 +1 兼容），原生 `:1375`/`:2177` 两处与分析器 `:95` 同规则消费。
3. 若维持"合法大弧不支持"的边界，请登记为显式待办条目并写入能力边界文档。

## 6. 🔍 `preview.view_matrix_matches` 恒 false —— 根因定位（回应 0.7.0 反馈 §8.1）

0.7.0 反馈中报告的"4 个成功 job 的 `view_matrix_matches` 全部 false"在本轮 3 个 job 上依旧复现。本轮完成根因定位：

`native/preview.h:75-81` 的比较逻辑：

```cpp
static bool preview_rotation_matches(const ProMatrix actual) {
    for (int row = 0; row < 3; row++)
        for (int column = 0; column < 3; column++)
            if (std::fabs(actual[row][column] - preview_isometric_view[row][column]) > 1e-3)
                return false;
    return true;
}
```

注释自己写明："**Creo applies its own shift and scale to the requested matrix, so only the rotation can be compared**"——但实现比较的是 `actual` 矩阵的**全部元素**（含第 4 列平移与 SDK 加的 scale/shift 踪迹），并非"only the rotation"。`ProViewMatrixGet` 返回的矩阵包含 Creo 自加的平移分量（第 4 列通常非零），所以 3×3 旋转部分即使完全一致，只要平移列不匹配就返回 false。

**建议**：比较范围改为行 0–2 × 列 0–2（纯旋转 9 元素），或对每行做模归一后比较。这是 3 行代码的修改，修完后 `view_matrix_matches` 才有诊断价值——目前该字段恒 false，等于没有信息量。
