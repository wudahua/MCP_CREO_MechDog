## 1. 结论先行

**0.23.1 修好的那一项我确认了；但本机仍然一步也走不了，而且失败点比 0.23.0 更靠前、更绝对。**

- `BUG-119`（`has_solid` 全局误判）方向正确、回执字段齐全，**但在 Creo 10 上这次修复根本无法进入验证**：`ProFeatureElemtreeExtract` 在 `has_solid` 判断之前就抛出，作业在 `extract_code = -18` 处终止。也就是说这条修复在低版本宿主上永远不会被执行到。
- `surface_loft` 在 Creo 10 上的失败形态没有变化：`create_code = 0`（特征被真实创建），随即 `extract_code = -18`，作业回滚，消息为 `surface_loft cannot extract the created feature tree (code -18)`。
- **这是本机唯一能建出「曲面」的 MCP 工具**。`surface_boundary_fill` 仍在 `unavailable_tools`（`capabilities.py:367 "surface_boundary_fill_unavailable"`），MCP 也没有任何几何导入通道（`grep "import_geometry\|Intf3DImport\|creo_import"` 在 `server.py` / `schema.py` / `native/generic.cpp` 零命中）。因此在本机 Creo 10 上，"用 MCP 曲面能力建一个过曲线的曲面"这件事**没有任何可用入口**，而不是"入口不好用"。

## 3. 关于「提取失败」的一点新证据（可直接用于修）

上一份文档已经证明：12 个 `ProFeatFormType` 全扫，**只有 `PRO_USE_SURFS(512)` 保留 `PRO_E_BNBLN_CURVES` 子树，并且只有 512 的树提取返回 `-18`**；能提取的 1024 / 262144 / 2097152 都是把 BNBLN 子树丢弃后当成别的曲面类型建的。本轮补一条**成本极低的替代判据**，供作者避免"先建空壳再回滚"：

**`ProFeatureIsIncomplete` 就能在提取之前判定这件事，不需要提取。**

实测（Creo 10，同一组曲线，5 个候选）：

| 候选 | `create_code` | `ProFeatureIsIncomplete` | 几何项 | 面 | quilt |
|---|---|---|---|---|---|
| 512 + `PRO_E_DTM_SRF_TYPE=11` | 0 | **true** | 0 | 0 | 0 |
| 1024 + 同 | 0 | **true** | 0 | 0 | 0 |
| 262144 / 2097152 + 同 | 0 | **true** | 0 | 0 | 0 |

即：**在这四个"创建成功"的取值下，特征一律是不完整空壳，一个几何项都没有。** 所以与其在 `create` 之后撞 `extract = -18`，可以在 `create` 之后立刻读 `ProFeatureIsIncomplete`，为 `true` 就带着这个明确原因失败，比现在的 `-18` 更能定位问题，也省掉一次注定失败的提取调用。

（另：`ProElemtreeVerify((ProSolid)solid, nullptr, tree)` 在 Creo 10 返回 **`-2 PRO_TK_BAD_INPUTS`**，文档承诺的"创建前校验"在此版本不可用，不能作为前置门禁。）

## 4. 对作者的请求（按对低版本用户的价值排序）

### A. 把"建空壳再回滚"改成"创建前/创建后立即判定"，不要先污染模型

现状：每次 `surface_loft` 调用都会在模型里真实创建一个 `PRO_FEAT_ACTIVE` 的不完整特征（id 62 / 64 / …），失败后靠回滚清除。虽然 `rollback_succeeded = true` 每次都成立，但：
- 模型 feature 计数会短暂变化，若客户端在作业进行中读取会被误导；
- 回滚是整作业级的，一旦后续加入更长的事务，空壳特征的副作用面会变大。

建议：`create` 之后立即 `ProFeatureIsIncomplete`，为真则以 `SURFACE_LOFT_KERNEL_INCOMPLETE`（携 `create_code` 与 `ProFeatureIsIncomplete`）失败，把 `extract` 留给真正需要的路径。

### B. 能力表显式暴露"本宿主能不能完成边界混合"

`creo_session_status` 的 `worker_build_identity.features.surface_loft` 现在只报 `available=true / state="compiled"`。对 Creo 10 这是**误导性的**：编译可用 ≠ 功能可用。建议增加一项运行期实测字段，例如

```json
"features": { "surface_loft": {
  "available": true, "state": "compiled",
  "kernel_completion": "unsupported",         ← 新增
  "kernel_evidence": {"create_code": 0, "incomplete": true, "extract_code": -18, "release_numeric": 42}
} }
```

这样客户端能在提交前就拒绝，而不是等一个必然回滚的作业。

### C. 低版本闭环：由 12.4 导出一次模板 XML（最省事、最彻底）

`ProElemtreeWrite / ProElemtreeFromXMLCreate` 在 Creo 10 SDK 中都有声明（`ProElement.h:3166 / 3207`），只是缺一棵正确的树。作者在 Creo 12.4 上（连提取都通）导出一次边界混合的元素树 XML，作为模板随包发布；低版本读入后只替换 `PRO_E_STD_CURVE_COLLECTION_APPL` 里的曲线引用再 `ProFeatureWithoptionsCreate`。**这条路完全绕开提取**，因为树是外部给的完整树。

### D. 或者：给低版本一条精确曲面入口

如果 A/B/C 都不做，建议提供一个 **STEP/IGES 曲面导入**操作。理由：低版本用户目前没有任何办法用 MCP 得到过曲线的曲面，而按精确 NURBS 数据导入在数学上与源数据等价（不是近似），至少能让"精确重建"这条路在 Creo 10 上走通。
