# 2026-11-12 + CREO + 0.23.2 + 低版本仍无可用曲面入口，而 Creo 10 SDK 本身已具备 STEP/IGES 导入接口

> 反馈对象：MCP_CREO_MechDog 作者
> 版本：`server_version = 0.23.2`，`worker_sha256 = b95cd7c2655b0799bb8efb6f68e21ac891157af970b42d78c135f53e5326864a`
> 宿主：Creo Parametric **10.0.0.0**，`creo_release_numeric = 42`
> 模型：`bulb_l030`（`806b9d5336354515986d9776bafff46f`），rev4，mm，SEC_A=40 / SEC_B=48
> 前置：`2026-11-12+CREO+0.23.1+surface_loft在Creo10因提取失败完全不可用.md`

## 1. 结论先行

**0.23.2 把我提的 A、B 两条做对了，本机逐字段验证通过。C、D 作者明确"未做"。**

所以本机 Creo 10 的状态没变：**仍然没有任何可用入口能建出一张过曲线的曲面**。但本轮查证到一条对作者很关键的事实——**路线 D 不需要等 PTC**：Creo 10 SDK 自带 `ProIntfimport.h`，STEP/IGES 导入是 Toolkit 公开接口。作者自己就能加，且成本不高。

## 2. 0.23.2 验收（A、B 两条落地确认）

```
job_id = be450d6a74bb4868acc1ddd3d897cd63

create_code        = 0
extract_code       = -18
extract_unsupported= true            ← 新增，符合请求 A
kernel_completion  = "unsupported"   ← 新增，符合请求 B
feature_incomplete = true            ← 创建后、提取前读取，符合请求 A
kernel_evidence    = { release_numeric: 42, create_code: 0, extract_code: -18, feature_incomplete: true }
message = "surface_loft created the feature (create_code=0) but this Creo release cannot
           extract its element tree (code -18, SURFACE_LOFT_EXTRACT_UNSUPPORTED);
           feature_incomplete=true, release_numeric=42; the job was rolled back"
rollback = succeeded
```

这条文案现在**不需要看原生日志就能定位问题**，比 0.23.1 的 `cannot extract the created feature tree (code -18)` 好很多。`ProFeatureIsIncomplete` 放在 create 之后、extract 之前读取，也正是我实测能判空壳的那个位置（四个可建 form 全部 `incomplete=true`、几何项 0）。

**B 的披露口径也对**：`available` / `enabled` 不因观测而变，只在 `worker_build_identity.features.surface_loft.kernel_completion` 里报 `unsupported`，未观测或 worker 不匹配报 `unknown`。我认同不据此做提交前预拒绝——预拒绝会把"某次作业失败"升级成"永久不可用"，粒度太粗。

**唯一遗留的体验问题**：即使有了 `kernel_completion="unsupported"`，`surface_loft` 每次调用仍会先在模型里真实创建一个 `PRO_FEAT_ACTIVE` 的不完整特征再回滚。能力表已经知道不支持，却仍允许提交，等于让用户用一个必然失败的作业去换一条已知结论。建议（低优先级）：`kernel_completion="unsupported"` 且 `release_numeric` 未变时，直接拒绝并不建特征。

## 3. 本轮新发现：Creo 10 SDK 已有 STEP/IGES 导入接口（路线 D 可行，无需等 PTC）

```
$ grep -rln "Intf3DImport\|IntfImport\|Intf3DFileRead\|ImportCadded" \
    "D:/Program Files/PTC/Creo 10.0.0.0/Common Files/protoolkit/includes"
./ProIntfimport.h
```

`ProIntfimport.h` 中的公开接口：

```c
extern ProError ProIntfimportModelWithOptionsMdlnameCreate (
        ProPath                  import_file,
        ProPath                  profile,          /* 可为 NULL */
        ProIntfImportType        type,             /* PRO_INTF_IMPORT_STEP / _IGES */
        ProMdlType               create_type,      /* PRO_MDL_PART 或 PRO_MDL_UNUSED */
        ProImportRepType         rep_type,         /* PRO_IMPORTREP_MASTER */
        ProMdlName               new_model_name,
        ProIntfimportLayerFilter filter_func,      /* 可为 NULL */
        ProAppData               application_data,
        ProMdl*                  created_model );
```

- 枚举里 `PRO_INTF_IMPORT_STEP`（值 6）、`PRO_INTF_IMPORT_IGES`（值 1）在 Creo 10 都齐（`ProIntfimport.h:14-33`）。
- 另有 `ProIntfimportSourceTypeGet()` 可在导入前判定该文件会建成什么模型类型，适合做前置校验。
- 旧接口 `ProIntfimportModelWithProfileCreate` 标记 `DEPRECATED: Since Creo 1`，应直接用 `...WithOptionsMdlnameCreate`。

**这一点改变了路线 D 的性质**：它不再是"要请 PTC 开能力"，而是"作者加一个约 40 行的原生操作"。对低版本用户（9/10）来说，这是唯一能在不依赖内核补全的前提下拿到**精确**曲面几何的通道——导入的 NURBS 曲面是数据本身，不是近似。

### 设计上请注意两点

1. **它是"新建模型"，不是"在已有模型里加特征"。** `created_model` 是一个新 part。若要让这根曲面进入主模型，还需要 `ProAsmcompAssemble` 装配或复制几何。建议把 import 操作设计成"导入到独立 part"，由调用方再用现有 `assemble_component` 组合，语义更干净，也避免主模型回滚时把导入件一起卷走。
2. **profile 传 NULL 时会用会话默认 profile**，且"profile 一旦设置就在整个会话内有效"（文档原文）。如果要保证导入结果可复现，建议由 MCP 显式传一个受管 profile 路径，并在回执里记录该 profile 的 SHA256。

## 4. 附带发现：GUI 手工建模后，MCP 连"导出/验证"都做不了（registry 漂移）

本轮想用现有模型验证"GUI 建 → MCP 导出/测量"这条路是否可行，实测被拦：

```
model   = bulb_guide_0200 (f24256bca72c4fa5b38d66762720a6a0)  rev5
op      = export format=step
job     = 7d38c7c2b8d14f589fee876e875f9bd7
结果    = BUILD_FAILED: model_reconciliation_required: Saved feature/body count changed
```

原因：用户在 GUI 里手工加过特征并直接保存，`model.json` 里记录的保存基线（feature/body 计数）与重新加载后的实测计数不一致，于是任何需要写盘的操作都被拒绝，`export` 虽然是只读导出也一样被前置拦截。

这一条对低版本用户影响很大：**即使愿意接受"GUI 手工建 + MCP 验证"的混合流程，MCP 也会先把手工建的几何挡在门外。** 目前只能由人工走 `creo_reconcile_model` 的 `accept_live` / `ack_no_mutation` 才能回到 ready，属于运维动作，不是建模动作。

建议（中优先级）：`export` / `inspect` 这类**不修改模型**的操作不要受保存基线漂移影响——或者在拒绝文案里直接给出可执行的下一步（现在的 `model_reconciliation_required` 只说了现象，没有把"用 `creo_reconcile_model` 的哪个 action"写进消息）。

另外记录一处已确认的事实：`bulb_guide_0200` 存档（prt.6）里只有 1 张 quilt，且是 `QUILT_PROBE`（feature 65，`surface_fill` 建的**平面**数据面），**不是**当时会话里用户手工建的那根边界混合（那根只在会话 prt.8，未进存档）。所以该模型不能作为球鼻艏的参考曲面来源。

## 5. 请求（本轮收敛为两条）

### 请求 1（高）：增加 `import_geometry` 操作，按第 3 节的接口实现

理由：这是低版本唯一可行的精确曲面入口，且 SDK 已有接口；作者侧实现量小；对高版本也有用（能导入外部精确曲面做比对/验证）。

最小可用形态：

```json
{"op": "import_geometry", "label": "bulb_srf", "file": "<abs path>",
 "format": "step", "new_model_name": "bulb_srf_import"}
```

回执建议带：`created_model_name`、`create_code`、`surface_count`、`area_mm2`、`quilt_closure`、`profile_path` + `profile_sha256`。

### 请求 2（中）：`kernel_completion="unsupported"` 时不要先建特征

见第 2 节末。现在是"建壳 + 回滚"换一条已知结论，收益为零。

## 6. 未测 / caveat

- `surface_loft` 在 **Creo 12.4** 上的成功路径本机无法复核（无 12.4 环境）；0.23.2 发布说明也声明本批未做实机，`kernel_completion="supported"` 的实机观测未取得。我不对 12.4 的行为做任何推断。
- `b_spline`、`boundary_conditions`、正交平面截面在 Creo 10 上同样到不了（都卡在提取），未复测。
- 第 3 节的导入接口只做了**声明层查证**（头文件 + 枚举），本机未实际调用；`PRO_TK_NO_LICENSE` 是否会在纯曲面 STEP 上触发、`rep_type` 取 master 的实际表现，需要作者或本机后续实测。
- 本文全部结论限于 **Creo 10.0.0.0**。
