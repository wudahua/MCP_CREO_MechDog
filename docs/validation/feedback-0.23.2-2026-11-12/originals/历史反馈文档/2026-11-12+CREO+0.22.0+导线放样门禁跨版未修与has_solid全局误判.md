## 一、结论先行

0.22.0 **又补齐了球鼻艏所需的一项关键能力**：首/末截面可以是收敛点
（`{kind:'point',id}` 或单点 `datum_points`），`sections`/`guides` 也接受已有曲线与 quilt 边。
这正是 11-11 反馈「即使修好门禁仍缺三项」中的第 ② 项，作者响应速度值得肯定。

但本次真机验收仍有**两个阻塞球鼻艏的问题**：

1. **【跨版未闭环】`Probbl.h` 门禁连续两版未修**。0.22.0 在 Creo 10 上提交 `surface_loft`
   仍是 `SURFACE_LOFT_SDK_UNAVAILABLE`，无 job、无几何。11-11 已给出可修复证据
   （Creo 10 的 `ProElemId.h` 有全部 `PRO_E_BNBLN_*` 常量，最小 C++ 探针 0 error），
   本次复跑仍 0 error，`native/surface_loft.cpp` 门禁段逐字未变。
2. **【本次新发现】`has_solid` 用"操作后全局状态"冒充"本次是否创建实体"，在已有实体模型上必然误判**。
   release notes 把「已有实体模型中 `surface_loft` 一律失败」归为「旧限制」，但源码显示这是
   `native/surface_loft.cpp:1073/1101` 的校验逻辑缺陷，**可修**。即使门禁修好，船体主模型
   （有实体）上放样仍会被这条误判回滚。

另有一个**反证很有价值**：0.22.0 新增的 `creo_measure_surface_group.open_edge_records`
在 Creo 10 上**实测完全可用**（4 条边、ID/端点/长度/面/quilt 齐全、0 failures）。
说明 Creo 10 的环境与内核本身没问题，**唯一障碍就是那一行头门禁**；
同时也形成了「供给端（quilt 边 ID）可用、消费端（`surface_loft` 的 `{kind:'edge',id}`）被编译剔除」的半条链路。

按用户「不做近似」要求，本轮**未**采用 TXT 行 92 的分段椭圆柱降级路径，主模型未改动。

## 五、【本次新发现】`has_solid` 全局误判——可修，不是「旧限制」

`native/surface_loft.cpp` 在放样成功后做结果校验：

```cpp
// 第 1073 行
details["has_solid"] = inspection(false)["has_solid"];      // ← 整个模型的全局状态
...
// 第 1101 行
if (details["has_solid"].get<bool>())
    throw std::runtime_error("surface_loft created solid material; a surface loft must not");
```

`inspection(false)` 查的是**操作后整个模型**是否有实体，而不是「本次操作是否新增了实体」。
因此只要模型**原本就有任何实体**（例如护卫舰船体主模型，`has_solid=true`），
无论放样本身是否只生成开放 quilt，`has_solid` 恒为 true → 必然抛错并回滚。
这正好解释 release notes 的「已有实体模型中 `surface_loft` 一律失败（原生 `has_solid` 看整个模型）」，
但它是**MCP 侧校验逻辑把全局状态当作增量**，不是 Creo 内核不能在有实体模型里建曲面。

**对球鼻艏的直接影响**：TXT B030 是「在船体模型内放样半体曲面 → 缝合 → 镜像 → 布尔合并」。
即使 P1 门禁修复，只要放样发生在 `frigate_txt_rebuild`（有实体）里，就会在这行被误杀；
只能绕到独立空零件建曲面再装配/布尔合并——**改变了 TXT 的特征树与建模顺序**。

**修复建议**：改为比较操作前后的状态增量，例如
`pre = inspection(false)["has_solid"]` 在创建特征前取一次，
只在 `!pre && post` 时判为「创建了实体」；或直接比较
`volume_mm3` / `bodies.with_material` 的增量，而不是看 `post` 的绝对布尔值。

> 证据边界：本结论来自 0.22.0 源码静态分析 + release notes 自述的实机现象，两者互相印证；
> 因 Creo 10 上门禁未开，**本机无法真机触发这条校验**。作者修复门禁后可直接复现验证。
> 本文不宣称已在 Creo 10 上跑出该错误。
