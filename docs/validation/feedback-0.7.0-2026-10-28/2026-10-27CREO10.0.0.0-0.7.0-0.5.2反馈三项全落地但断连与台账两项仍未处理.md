## 2. ✅ 我 0.5.2 的三项建议全部落地（这次做得很彻底）

### 2.1 会话健康探针 → `session_health`（T10，BUG-078）

`src/creo_mechdog/session_health.py` 的设计正是我建议的方向，而且比我想的更克制：

```
The summary is derived only from execution results that already exist on disk:
job manifests ... plus the last persisted Toolkit probe result.
It never opens a Toolkit connection or channel lock, never saves,
never probes Creo, never writes a file and never clears a protection ...
```

- 三值：`unknown` / `suspected_damage` / `no_failure_observed`；对外还带 `next_steps`；
- **并且明确写清了语义边界**："`no_failure_observed` is an evidence label, not a health guarantee…
  A successful connection does not prove that the next Backup will succeed."
  —— 这句话非常重要，它防住了"看到健康就放心提交作业"的误用。

### 2.2 显式世代回收 → `creo_reclaim_generations`（T11，DEV-027）

这正是我 0.4.5 起反复提的"dry-run 只有盘点、没有执行"的收口：

- `mode=inspect|apply`；600 秒证据令牌绑定目标、目录内容摘要与引用证据；
- apply 复用通道锁互斥、路径限定在 `build/blend_loader|blend_callback` 自有根、拒绝穿越/重解析点；
- 幂等键回放不重复删除；**当前/注册/运行中/回退保留世代一律保留**；
- 源码注释也体现了保守原则："anything unproven keeps the directory"（`generation_reclaim.py:250`）；
- 启动与普通查询**不自动清理**。

我此前最担心的是"候选判定误列 → 误删正在用的世代"，这条实现是**朝保守方向**收的，我认可。

### 2.3 README 单位口径 → 不只是补一段，而是**通则化**

我 0.5.2 §2.4 建议"把非毫米单位写进新增接口的必测矩阵"。README 现在的写法（第 27–29 行、第 259 行）：

- 明确 `transform_to_parent` / `transform_to_root` 是**毫米归一化**，`*_raw` 不可直接当毫米参数；
- 给出**混合单位换算公式**：`p_parent_mm = p_local_mm × (s_parent/s_local × R_raw) + s_parent × t_raw`，
  并点明"混合单位影响 3×3 块与平移，不能只缩放平移"；
- 第 259 行更写成了一条**通则**：
  > 这组矩阵是后续新增数值接口（坐标、变换、体积等）的**验收模板**：新接口必须在**毫米、英寸、混合与未知单位四种场景**下分别取得证据，
  > 未知或查询失败如实为 `null`，**不得默认毫米**。

这比我的建议更进一步 —— 从"修一条字段"变成了"定一条规则"。

## 6. ✅ 本版其他值得肯定之处

- **T02 统一操作结果状态**：每个输入操作发布恰好一条带零基 `index` 的结果，并区分
  `execution_status`（succeeded/failed/not_executed/unknown）与 `effect_status`（committed/rolled_back/no_effect/unknown），
  失败作业也返回完整 operations 列表、失败项之后补 `not_executed`+`no_effect`。
  这套"执行到没执行到"与"有没有实际效果"分开的表达，比单一 `success` 布尔对自动化可靠得多。
- **T08 `feature_state` 不自动级联**：抑制/删除若涉及 Creo 会隐式处理的伴随基准，**整批拒绝并返回依赖清单**，
  要求显式列出。这比"帮用户猜"安全。
- **T09 装配回放规划的"整组设置"**：明确写了"原生 setter 替换整组约束集，逐约束生成会静默丢失"，
  所以先插全部组件、再按组件整组设约束 —— 这类"知道原生 API 陷阱并在设计上绕开"的说明很有价值。
- **T13 主动披露五处生产修复**（含 `system_required` 误标导致抑制死锁、回放逐约束生成只剩最后一条等），
  把集成矩阵暴露的问题如实写进发布说明，而不是悄悄改掉。
- 966 项单元测试通过；`setup.ps1` 在全新目录 exit 0；正式包与安装候选按 LF 归一化逐文件核对。
