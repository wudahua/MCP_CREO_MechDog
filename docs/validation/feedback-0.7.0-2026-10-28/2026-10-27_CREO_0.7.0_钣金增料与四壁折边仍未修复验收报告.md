## 二、仍未修复项（复现细节）

### S1 钣金件增料 ❌（五轮未修，最高优先级）
- 用例：`acc70_sm`：185×232×232 钣金壁 → 草图矩形 X 88..98 / Z 100..110 于 XZ 面 → `extrude(mode="add", depth=10, direction=negative)`。该块与实体**真实体积重叠**（X 88..92.5 段），已排除"无重叠/仅共面"误判。
- 结果：`ProFeatureWithoptionsCreate=-1`。
- **但报错质量显著提升**（值得肯定）：
  > "Extrude feature creation failed (ProFeatureWithoptionsCreate=-1). Toolkit rejected the referenced sketch section; the return code alone does not identify whether closure, a geometric condition or the feature tree caused it. Detected native section: 1 closed contour(s), 1 contour(s), 4 entity(ies), 0 open end(s). These counts do not identify the cause; **the cause is not determined**."
  即：工具明说"原因未确定"，并给出截面诊断，不再虚构归因。这比 0.3.1 的裸 `code -1` 好得多。
- **仍建议优先修**：同一截面同一实体在**普通零件**上增料成功（v0.3.2 已修 P1 后验证过），在**钣金件**上必失败 → 强烈指向"钣金模型上的 protrusion 走了一条不同的实现路径"，而非截面几何问题。

### S3 封闭四壁盒 ❌（五轮未修）
- 用例：`acc70_sm2`：185×232×1 底板 → 一次挂 4 道折边（h=80, R2.54, Y=0.5，边 104/105/106/107）。
- 结果：`f_px`、`f_nx` 成功；**`f_ny` 失败**（`ProFeatureWithoptionsCreate=-1`），`f_py` = `not_executed`。
- 与 0.3.1/0.3.2/0.3.3/0.3.5 完全一致；仍无折弯释放（bend relief）参数 → 垂直折边在角部必然冲突。

### S5 `depth=1` ❌（五轮未修）
- 用例：`sheetmetal_wall(depth=1.0, thickness=232.0)`，草图线长 185。
- 结果：体积 **9 957 440 = 185×232×232**（应为 42 920），`center_of_gravity` 也印证 Z 方向质心 116（板厚 232 的一半）。`depth` 被静默替换为 `thickness`。
- 连带：仍无法用 `sheetmetal_wall` 直接铺 1 mm 底板，必须绕道（YZ 平面 + offset、thickness=1、depth=面内长边、direction=negative）。

## 三、本轮已修复 / 显著改善项（值得肯定）

### ✅ S10 逐项结果已修复
失败时 `result.operations` 不再为空，而是逐项返回：
```json
{"op":"sheetmetal_flange","index":2,"label":"f_px","execution_status":"succeeded","effect_status":"rolled_back"}
{"op":"sheetmetal_flange","index":4,"label":"f_ny","execution_status":"failed","effect_status":"rolled_back"}
{"op":"sheetmetal_flange","index":5,"label":"f_py","execution_status":"not_executed","effect_status":"no_effect"}
```
可精确知道"哪几项已成功、失败在哪一项、哪些未执行"，**可以直接只重跑后半段**。这正是前几轮建议的内容，已落实。

### ✅ 诊断与可观测性大幅升级
1. **失败信息诚实且带截面分析**：不再虚构归因，明确 `the cause is not determined`，并给出 `native_section`（contours / entities / open_ends / branched_points / tolerance）。
2. **草图分析**：每个 sketch op 返回 `profile`（`contour_count`、`closed/open`、`material_area_mm2`、以及 open/branched/self_intersecting/intersecting/tangent/zero_area/near_tolerance/unsupported 八类计数）+ `native_section`，能快速判断截面是否闭合、是否自交。
3. **`session_health` 证据块**（`creo_startup_status` 新增）：会话指纹、通道占用者、最近连接/保存结果、`damage_signals`、`next_steps` 恢复指引，并明确声明 `guarantee: evidence_only`。这对跨日断连（前几轮的 S7）非常有用。
4. **`inspection` 增强**：新增 `center_of_gravity`、`length_unit`（含 `scale_to_mm` 与各查询码）、`units_query_code`；模型列表新增 `feature_state`（tombstone/suppressed 计数）、`part_sha256`、`adopted`、`source_kind`。
5. **可追溯产物**：`inspection_ref` / `aliases_ref` 给出落盘文件的路径 + sha256 + 字节数，`session_fingerprint`、`creo_release_numeric`（42）一并返回。
6. **preview 分步诊断**：`preview` 块把 display/window/refit/repaint/raster 每一步的返回码都列出，并给出 `failed_step`/`failed_code`。

## 四、本轮新发现

### N3. `preview` 生成间歇性失败（`output_file -4`）
- 4 次建模调用中有 2 次（含**全新的空零件**）返回：
  `preview_status: "failed"`, `failed_step: "output_file"`, `failed_code: -4`, `bytes: -1`，而 `preview.codes` 里 display 到 raster **全部为 0**（即渲染链路都成功，只是写文件失败），且 `view_matrix_matches: false`。
- 影响：无预览图可供人工核对（本次复现 S3 时就没有预览可看）。
- 建议：`output_file` 失败时给出目标路径的存在性/权限/占用信息（是否被上一次 job 的句柄占用），或失败后自动重试一次。

### N1 仍存在
钣金件 `inspection.counts.bodies` 仍恒报 2（单个 6 面/12 边实体也报 2），实体件正确报 1 → 该字段对钣金件不可用。

## 五、建议（按收益排序）

1. **修 S1（钣金件增料）**——五轮未修，钣金链路唯一硬阻塞。**重要线索**：同一截面在普通零件上增料正常，在钣金件上必失败，请对比两条 protrusion 实现路径（父特征/默认 body 选择、`ProFeatureWithoptionsCreate` 的 options 差异）。
2. **修 S3 + 提供折弯释放**（`relief` 参数：矩形/扯裂/圆形，或自动角部处理）。
3. **修 S5**：`depth` 不应被 `thickness` 覆盖；并在工具描述中画清 `线长 / thickness（面内、以线为中心）/ depth（垂直草图平面）` 三个方向。
4. **N3**：修 `preview` 的 `output_file` 失败（给出占用/权限信息或自动重试）。
5. **P11**：`creo_export_model` 增加 `native_bundle`（.asm + `C_*.prt` 快照一起导出）。
6. **N1**：修正钣金件 `bodies` 计数或注明不可靠。
7. **P5 / S2 / S6 / P3**：前几轮已详述，仍未修，建议一并排期。
8. **changelog**：0.3.5 → 0.7.0 跨了 4 个版本号，建议在 `creo_capabilities` 中提供变更记录，便于回归定位。
