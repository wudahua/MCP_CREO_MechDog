## 2. 【已修复】非主轴基准面拉伸方向

### 2.1 干净零件上的定量验证

被测件 `probe_npp_v061`（`5582d653e2f14acda4d65d93c0ad5cfd`）：R20 圆板 × 5 厚；倾斜面 id 74，法向 (0.587785, 0.809017, 0)，过原点；截面为 4×6 矩形（u∈[0,4]，v∈[−3,3]），`normal`/`u_axis`/`v_axis` 由 v0.7.0 回显确认，v_axis = (0,0,−1)。

`creo_extrude(mode='cut', direction='positive', depth_type='through_all')`：

```
material_removed_mm3 = 238.3902600633137
```

**解析核对**：该扫掠的每一条射线沿 +n 走，到 Z 轴的距离恰为 |u|（因 0.809²+0.588² = 1.000），板半径 20 时半弦长 = √(400−u²)；v 方向在板厚内只取 v∈[−3,0]（即 z∈[0,3]），故

```
V = ∫₀⁴ √(400−u²) du × 3
  = [ u/2·√(400−u²) + 200·asin(u/20) ]₀⁴ × 3
  = (2×√384 + 200×0.20135792) × 3
  = 79.463424 × 3
  = 238.390
```

**实测 238.390260 vs 解析 238.390 → 6 位有效数字一致。**

对照 v0.6.1 同一场景（当时是 `direction='positive'` 且几何等价，仅矩形在 u∈[−4,0]）：实测 **120.0000 = 4×6×5（截面面积 × 板厚）** —— 即沿全局 Z 扫。两个版本的数字差异本身就是修复的直接证据。

### 2.2 面级复核（不再需要）

上一版需要通过"侧面 Z 跨度等于材料 Z 范围"来反推方向；本次体积解析已经闭合，无需面级推断。

### 2.3 残留影响

Part1 的 P02 之所以仍没建成，**原因已不是方向**，而是 §5 的草图问题。

## 3. 【已修复】`u_axis` 为纯轴向

规格 Part2 要求 `(u,v) → 全局 (0, v, −u)`（u 沿 −Z）。v0.7.0 实测：

```json
"plane": {"reference": {"kind":"datum_plane","id":2}, "origin":[0,0,0], "u_axis":[0,0,-1]}
→ succeeded
  surface_id: 2, normal: [1,0,0], u_axis: [0,0,-1], v_axis: [-0.0, 1.0, 0.0]
```

v_axis = (0,1,0) 正是规格要求的手性。**`Zero direction vector` 不再出现。**

更值得称赞的是：`creo_create_sketch` 现在会**回显实际使用的坐标系**（surface_id / origin / normal / u_axis / v_axis）。这直接消除了我前三份报告里"无法校验草图帧"的痛点——本次所有实验都能自证帧是否正确。

## 4. 【未修】多轮廓截面仍只支持 2 个（但诊断已达标）

同一版本、同一零件（`probe_npp_v061`）上的干净对比：

| 轮廓 | 实体 | 结果 |
|---|---|---|
| 2 个独立圆（R2，±8,0） | 2 | ✅ `material_removed_mm3 = 125.663706`（= 2·π·4·5，精确） |
| 5 个独立 4 弧链闭环 | 20 | ❌ 失败 |

v0.7.0 的报错**已经完全按我上份报告的建议改写**，非常好用：

```
Extrude feature creation failed (ProFeatureWithoptionsCreate=-1).
Toolkit rejected the referenced sketch section; the return code alone does not identify
whether closure, a geometric condition or the feature tree caused it.
Detected native section: 5 closed contour(s), 5 contour(s), 20 entity(ies), 0 open end(s).
These counts do not identify the cause; the cause is not determined. Sketch: 'probe_gear5_sk'.
```

它明确告知：**5 个闭合轮廓、20 实体、0 个开放端** —— 截面本身没问题，失败在别处。作者拿到这句话就能直奔 `ProFeatureWithoptionsCreate` 的 section 传参路径，不必再怀疑轮廓。

**仍待解决**：为什么 2 contour 通过、5 contour 被拒。建议在 section 构建处打印每个 contour 的 loop ID 与材质侧，或加一条回归：`2 圆 + 5 个 4 弧链闭环` 必须同时通过。用例：`scripts/gear10.json`（10 环 40 弧，取前 20 条即 5 环）。

## 5. 【新问题】非主轴面草图在"新建零件"上无法自动标注

### 5.1 现象

| 模型 | 平面 | 截面 | 结果 |
|---|---|---|---|
| `part1_star_v2`（**本次新建**的星形架） | id 163，法向 (0.588,0.809,0) | 30 段斜槽闭环 | ❌ `AutodimensionSketch = -1` |
| 同上 | 同上 | **同一个 30 段截面，改 `coordinates`** | ❌ 同样落到 `AutodimensionSketch = -1` |
| 同上 | 同上 | 4 线矩形 u∈[−4,0] | ❌ 失败 |
| 同上 | 同上 | 4 线矩形 u∈[0,4] | ❌ 失败 |
| `probe_npp_v061`（含圆盘实体） | id 74，法向相同 | 4 线矩形 u∈[0,4] | ✅ 成功 |
| 同上 | 同上 | 4 线矩形 u∈[−4,0] | ✅ 成功 |
| `part1_star_frame`（**旧**星形架，0.5.2 建的） | id 163，法向相同 | 4 线矩形 | ✅ 成功 |
| 同上 | 同上 | **30 段斜槽闭环** | ✅ 成功（`material_area_mm2 = 15.57317477042468`，30 实体 1 闭环） |

### 5.2 关键判断：不是截面问题

同一份 30 段截面在旧零件上**成功**，且工具自带的 profile 分析每次都证明它合法：

```json
"profile": { "entity_count": 30, "contour_count": 1, "closed_contour_count": 1,
             "open_contour_count": 0, "material_area_mm2": 15.57317477042468,
             "categories": { 全部为 0 } }
"native_section": { "closed_contours": 1, "contours": 1, "curves": 30,
                    "open_ends": 0, "unsupported_entities": 0, "tolerance_mm": 1e-6 }
```

即：**轮廓合法、面积正确、无任何缺陷，autodim 仍然失败。**

### 5.3 也不是"位置/u 侧/复杂度"

- 4 线矩形在 part1_star_v2 上**两个 u 侧都失败**；同一矩形在 probe_npp_v061 上**两侧都成功**。
- 30 段截面在旧 Part1 上成功 → 与实体数量、R0.25 小弧无关。

### 5.4 最可能的原因（待作者确认）

三个模型的首个倾斜面草图：

| 模型 | 该平面的**第一次**草图 | 结果 | 之后 |
|---|---|---|---|
| `part1_star_v2` | 30 段截面 | ❌ 失败 | 之后同一平面**全部失败**（4 次） |
| `probe_npp_v061` | 4 线矩形 | ✅ 成功 | 之后全部成功 |
| `part1_star_frame` | 4 线矩形（0.5.2 时） | ✅ 成功 | 之后全部成功 |

**推断：一次 `AutodimensionSketch` 失败会污染该平面（或该模型）的草图状态，导致后续所有草图在同一平面上都失败。** 这与"旧零件能建、新零件建不了"完全吻合。建议验证：在新零件上先建一个 4 线矩形（应成功），再建 30 段截面，看是否仍失败。

### 5.5 影响

P02（5 条贯穿斜槽）在 v0.7.0 里仍然建不出来 —— 但**卡点已经从"方向错"变成"草图建不出来"**。因为这条阻塞，本次没能把 Part1 补成完整件，也没能验证 `axis_pattern` 在真实斜槽上的表现。

## 6. 其它变化

### 6.1 可观测性大幅提升（值得肯定）

| 新增 | 价值 |
|---|---|
| `creo_create_sketch` 回显 `surface_id`/`origin`/`normal`/`u_axis`/`v_axis` | 草图坐标系可自证，彻底解决"帧到底对不对"的争议 |
| `profile` 分析块（contour_count / closed / open / material_area_mm2 / 7 类缺陷计数） | 失败时能立刻区分"轮廓非法"与"工具内部问题" |
| `native_section`（contours / curves / open_ends / reference_entities / tolerance_mm） | 与 profile 交叉校验，本次 §5 的结论就靠它 |
| `creo_inspect_model` 新增 `datum_axes` 段；`creo_datum_axis` 返回 `direction`/`origin`/`id` | 轴可读，阵列前可校验 |
| `creo_get_job` → `preview{status, codes{failed_step, failed_code,…}}` | 预览失败能定位到具体步骤 |
| `creo_startup_status` → `session_health`（session identity 变化、历史 unknown_outcome、恢复建议） | 会话健康可判定 |
| 错误信息带 sketch 名与 native section 计数 | 见 §4 |

### 6.2 仍存在

| 问题 | 说明 |
|---|---|
| **无删除特征** | `supported_features` 仍无 delete。本次为定位问题又留下 `part1_star_v2`、`probe_npp_v061` 两个探针零件与 8 个探针草图 |
| **无批处理** | 1 特征 = 1 job（8–25 s，每次 save+reload+verify）。本轮 4 零件+装配 ≈60 特征 |
| **`creo_extrude` 无拔模 / 无显式方向向量** | 方向问题虽已修，但 `direction_vector:[x,y,z]` 仍建议加，作为兜底与自证手段 |
| **label 规则未文档化** | `^[a-z][a-z0-9_]{0,27}$`，报错不提示"改小写" |
| **`preview` 仍报 `view_matrix_matches: false`** | 多次 job 里视图矩阵与模型不匹配；虽然 `status: written`，但目视仍不可靠 |
