# 2026-10-10 安装与普通混合问题核实及修复

针对用户提供的《2026-10-10MCP更新安装问题》，核对源码，并在 Windows x64 / Creo 10.0.0.0 实机复现。保留版本号 0.2.4；此修复位于历史 v0.2.4 发布之后，不能将历史发布包当作已经包含修复的包。

| 问题 | 核实结论 | 修正 |
| --- | --- | --- |
| P1 读取 Blend 编辑参照返回 -2 | 确实复现，但“环境变化所以不是代码问题”的结论不成立。确认旧代码存在活动模型上下文和种子按名称复制两项缺陷，早期成功不能排除它们 | 显示并用 `ProWindowActivate` 真正激活；复用当前/基础窗口，检查活动模型；保存重载及模式检查采用相同上下文。指定 `.prt.N` 快照按字节复制为唯一模型，避免名称/版本搜索及已加载模型碰撞 |
| P2 所有放样截面必须显式 dimensions | 结论过强。旧实现中相同大小的空尺寸矩形确实在重排失败；圆形和翼型空尺寸并不需要这一条件。父项查询发现新矩形草图引用种子 Blend，形成不可重排的依赖 | 创建截面期间临时抑制新副本的种子混合，随后恢复；重排前检查新截面没有依赖旧混合/旧截面。dimensions 保持可选，命名参数仍建议显式提供 |
| P3 旧 constants.inc 不会自动更新 | 确实存在升级风险。旧构建指纹已经包含 `.inc`；缺陷是检查缓存之前未更新生成文件 | 每次构建执行幂等生成，再核对缓存；SDK 头文件内容也计入指纹，数值变化但常量名不变时仍重新编译 |
| P4 坏的许可文件路径挡住 PSF | 确实存在；本机检测到环境路径不存在、PSF 文件路径存在 | 未设置或所有本地路径都失效时在子进程中回退；有效文件/目录/服务器及仍含有效项的列表保留。环境工具返回不含许可值的诊断，不改系统变量 |
| P5 构建失败留下安装中间状态 | 确实存在；保留中间文件本身是可恢复设计，但旧脚本没有客户端配置及恢复说明，还会丢失额外本机配置字段 | 虚拟环境后提前生成客户端配置；报告失败阶段、已完成步骤及重跑方法；保留额外配置、会话选择、模型与任务。配置存在不等于安装成功 |
| P6 Windows SDK 探测受阻却只报 stdio.h 缺失 | 外部安全策略不是项目代码缺陷，但项目诊断不足 | 在 vcvars64 后检查编译器、链接器、UCRT/UM 头文件及 x64 库；单独返回构建前置检查失败并提示 SDK/注册表探测。不会更改安全策略或自动绕过它 |
| P7 安装文档未列公制装配模板 | 确实存在文档缺口 | INSTALL.md 明确列出零件和装配两份模板；环境检查与安装器的前置文件清单统一 |

PTC 文档明确说明 `ProWindowCurrentSet` **不等同于激活窗口，也不影响 `ProMdlCurrentGet` 的活动模型**：[官方接口说明](https://support.ptc.com/help/creo_toolkit/protoolkit_plus/korean/creo_toolkit/api/dita/6316.html)。本项目运行异步图形 Toolkit 执行器，使用 [ProWindowActivate](https://support.ptc.com/help/creo_toolkit/protoolkit_pma/r12/spanish/creo_toolkit/api/dita/6307.html)。完整 API 参照说明未列出“切换工作目录令句柄失效”的条件，本轮也没有观察到这样的证据；不将该猜测写成前置要求。

**旧种子模式变化的证据已独立核实**：报告中 SHA256 为 `9665650c…bc2af` 的原文件保持不变，按准确文件加载并激活后，原生模式为 `straight`；旧成功任务实际生成的隔离复制文件 SHA256 为 `8503cb62…8f0fd`，原生模式为 `smooth`。这两份文件各自重新建模、保存重载后模式一致，源文件不变。旧任务记录中的 `seed_sha256` 只标记请求快照，不能证明按名称复制 API 实际使用了同一份数据；“同一哈希读出了不同模式”不能据此归因于外部环境。修复后两份诊断输入的隔离文件均逐字节匹配各自快照。

## 验证

- 36 项 Python 回归测试通过，分别验证 Python 3.12 和 WorkBuddy 原有 Python 3.13 环境。其中新增 7 项覆盖许可回退与脱敏、本机配置保留、旧常量表更新、SDK 数值变更使缓存失效、编译环境预检和真实 PowerShell 安装中断恢复。安装测试使用独立假 SDK/临时虚拟环境，不修改真实 Creo 安装或用户配置。
- 真实 MCP stdio：6 个建模案例，均通过原生 Blend 身份保留、参数修改及保存擦除重载。另验证无效特征 ID 和模式不匹配确实被拒绝，共 14 个任务。
- 三份官方种子测试前后 SHA256 一致；不改动用户源 PRT。
- 另用 2 个新零件诊断旧原文件与旧复制文件，确认原生模式、保存重载、源文件不变和准确快照复制；不将这两个诊断零件计为上述参数修改案例。
- Python 依赖、Creo Toolkit 许可和各客户端安全策略仍由目标机实际环境决定；构建前置检查不会将“文件存在”称为“取得许可”。本机实际建模成功验证了当前连接路径可用。
