## 交付方式及取舍

用户选择自行分配 agent 或对话窗口，因此采用分窗任务包。共用一份派发表，既有问题沿用原 ID，新问题先由登记任务核号入账；不把所有新反馈塞回 DEV-051，也不建立第二套台账。

同一 checkout 的共享源码修改串行，或在隔离工作区完成后由指定集成人整合。离线只读分析可并行。原生构建、执行器替换与全部 Creo 实机均由一个负责人串行调度；实机期间禁止其他窗口重建 worker。

## 验收与约束

- 所有本机联调只使用指向 `E:\Projects\MCP_CREO_MechDog` 的 `MCP_CREO_MechDog_dev`。
- 默认阶段为离线。用户指派完整/实机阶段且当前 BUG-001 会话条件得到确认后，才执行该阶段；历史 ready 或命令行确认开关不能替代当前条件核对。
- 不擅自启动、结束或重启 Creo，不清 unknown，不注入故障。busy 不排队、不自动重试，已受理任务只轮询；unknown 或挂起时停止新提交并保留现场。
- Python 只校验和投影，几何与实际方向证据来自原生执行器；无法查询为未知并保留原始码。
- 原生验收必须有成功终态、原生特征/几何/参数、`saved_file_reloaded_and_verified=true`，适用失败路径有回滚、revision 与恢复后合法操作证据。
- WorkBuddy 如另行指派，严格使用公开 MCP 黑盒验收，不执行本计划的源码、单元或本地脚本步骤。
- 历史反馈原件逐字节不变；新材料复制归档并核 SHA256。运行数据、SDK、许可、常量表与二进制不入源码包。
- 各任务独立交接，离线完成不冒充实机通过，调查完成不冒充缺陷关闭。main/版本/正式 Release 只交给用户指定的最终集成人。
