# MCP_CREO_MechDog 0.9.0

0.9.0 交付 [DEV-051](work-items/DEV-051.md) 本轮的实机修复与定因结果。新增公开参数 `creo_sheetmetal_flange(end_trim_mm)`（可选、正数、缺省不变），并把零件级板厚同步改为由 `SMT_THICKNESS` 参数驱动——两者都是对现有工具的行为修正，无新增工具，公开工具仍为 **94** 个。按版本规则属 **MINOR**。0.8.0—0.8.5 的提交、标签、Release 和附件均保持原样。

## 升级必读

- **首壁板厚语义修复（BUG-032/T03）**：`sheetmetal_wall` 现在把零件级钣金厚度（`ProSmtPartThicknessGet`/`ProSmtPartThicknessValueGet`）同步到请求值——实机证明直接写维度是空写（再生按钣金关系回填模板默认），本版改写 `SMT_THICKNESS` 参数并再生、复验体积与回读，任一不符即失败。1 mm 壁的零件厚度实机读数从 3.71 变为 1.0，五组 depth/thickness 矩阵体积误差 0.0，`saved_file_reloaded_and_verified=true`。依赖零件级厚度读数的下游逻辑从此得到正确输入。
- **`creo_sheetmetal_flange(end_trim_mm)`**：可选诊断参数，把折边在链两端按给定长度缩短。语义（链端 setback）尚未实机确认，使用前先在自由首壁上做探针；缺省不写即行为不变。
- **能力边界更新（实机定因）**：折边的附着边**端部与既有折弯相邻时必然失败并回滚**——自由整条边可建，被前一道折弯吃掉一端（185 → 181.46 mm）即失败。四壁不支持，corner relief 未实现；`creo_capabilities` 的 sheetmetal limits 已按此更新。

## 本轮实机与验证范围

- **T03 首壁板厚：实机通过**（5/5 矩阵 + 拒绝例，见上）。green/white 面距未单独量测。
- **T13 `native_bundle`：两段式实机通过**。导出 `complete=true`（3 文件，SHA256 全部核对）；同会话回导因 `SESSION_NAME_CONFLICT` 被拒（受管模型不可经 MCP 擦除，且装配检索要求空会话），改用隔离会话后回导通过：组件 2/2、位姿逐项一致、`occurrence_label` 保留。驱动新增 `--reimport BUNDLE --expected REPORT` 两段式模式。
- **T05/T11 第三道折边：已定因，仍开放**。对照实验证明失败条件是“附着边端部与既有折弯相邻”（单端即可），与释放参数无关；因此 `relief` 的材料场景仍未验证，`none/1×1/4×4` 对比没有跑起来。自由端两道折边增量与独立 oracle 差 7e-7 mm³。
- **T09D 性能基准：已出数据**。small（36 边）单操作 19.5 s / 批量 11.3 s；large（8 切槽）单操作 261.0 s / 批量 138.7 s，等价校验全通过；分段耗时在 MCP 层结构性不可观测。large 类未达 3 次重复。
- **离线交付（未实机）**：T02 弧方向驱动判定修复（体积不再是充分证据，重载标志只认 `result` 块）、T09B 中心线计数剔除系统投影参考（一条用户线计 1）、T09A 组件标签回归锁定（生产零改动）、T12 沉孔余项用例（盲孔/方向/编辑/回滚，全部待实机）、BUG-085 离线证据调查（**根因未定**：0.6.1 断连与 10-29 挂起同码不同根）。
- **T09B 中心线计数**的修复已实现但只做了离线与静态验证，未实机复测。
